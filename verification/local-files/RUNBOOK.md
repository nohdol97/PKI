# 로컬 파일 수집 배포처 검증 절차서: Windows 설치본에서 W1~W12 (S23)

> **상태: 작성만 됨 — Windows에서 실행된 적 없음.** 사외에서는 거부 두 경우, `prepare`의 파일 만들기, 기록 양식만 단위 시험(`python3 -m unittest discover -s verification`)으로 돌렸고 그 통과는 배포처 결과가 아닙니다. 이 문서도 Windows 동작을 확인된 것으로 적지 않습니다(I02B-R45).
>
> 스펙: [I02-B spec](../../docs/specs/2026-11-22-I02-local-file-import.md)(I02B-R44, "Windows에서 확인할 것"), 배포처 항목: [site-setup.md S23](../../docs/site-setup.md).

## 1. 이 검증이 하는 일

설치된 앱은 `pnpm`도 작업 공간도 갖고 있지 않습니다. 그래서 실행기(`run.py`)는 이 저장소의 Python으로 돌고 **설치된 앱을 밖에서 봅니다.** `prepare`가 시나리오 W1~W12의 파일을 빈 폴더에 만들면, 사람이 설치본에서 그 폴더를 승인하고 아래 4절의 순서(이름 바꾸기, 디스크 뽑기 등)를 따른 뒤 앱을 닫습니다. `record`가 정본을 **읽기 전용으로** 열어 항목별 결과(통과·실패·판정 불가)와 OS, 앱 버전, 파일 시스템 종류를 JSON으로 적습니다. **파일 이름과 글은 기록하지 않습니다.**

## 2. 처음 나오는 말

| 말 | 뜻 |
|---|---|
| 설치본 | R04의 설치 파일로 설치한 앱. 실행기는 실행하는 OS가 Windows이고 `--app`이 가리키는 폴더에 설치된 실행 파일(`*.exe`. 제거 프로그램은 아님)이 있을 때만 설치본으로 봅니다 |
| 표식 | 시나리오 파일의 글에 넣은 무작위 글자 덩어리. 정본에서 그 파일이 원본이 되었는지 찾는 데만 쓰고 기록에는 적지 않습니다 |
| 상태 파일 | `prepare`가 표식을 적어 두는 파일(기본: 폴더 옆의 `<폴더 이름>.local-files-state.json`). 폴더 **안**에 두면 앱이 그 파일을 문서로 읽어 버리므로 밖에 둡니다 |
| 정본 DB | 앱의 데이터 폴더(`%LOCALAPPDATA%\PKI\pki.sqlite`)에 있는 SQLite 파일 |

## 3. 준비

1. 깨끗한 Windows 11에 R04의 설치 파일로 앱을 설치합니다. 이 PC에서 원본 실행으로 앱을 켜지 않습니다(같은 데이터 폴더를 씁니다).
2. 이 저장소를 받은 폴더와 Python 3.8 이상(표준 라이브러리만 씀). Windows의 `python3`는 Store 바로 가기일 수 있으니 아래 명령은 `python`을 씁니다.
3. 합성 자료만 씁니다. 실제 업무 자료를 넣지 않습니다.
4. 빈 폴더를 하나 만듭니다(예: `C:\pki-lf\docs`). 앱의 데이터 폴더 안이나 그 아래는 안 됩니다.

## 4. 순서

```
python verification\local-files\run.py prepare --app "C:\Users\<이름>\AppData\Local\Programs\PKI" --folder C:\pki-lf\docs
```

1. `prepare`가 `w01`~`w12` 폴더를 만듭니다. 설치본이 아니면 `배포처 후속`으로 시작하는 알림을 내고 3으로 끝나며 아무것도 만들지 않습니다.
2. 앱을 켜고 설정의 "로컬 자료"에서 그 폴더를 "폴더 추가"로 승인합니다. 훑기가 끝나기를 기다립니다(안정화 시간 2초 이상).
3. 시나리오마다 아래 동작을 하고 다음 훑기(또는 "전체 다시 훑기")를 기다립니다.

| # | 하는 일 | 실행기가 정본에서 보는 것 | 사람이 `answers.json`에 적는 것 |
|---|---|---|---|
| W1 | `w01\before.md`를 같은 폴더 안에서 이름 바꾸기, 다른 하위 폴더로 이동, 편집기로 바꿔치기 저장 | 표식이 든 원본이 하나이고 삭제되지 않았는지(통과), 둘 이상이거나 삭제됐는지(실패) | 파일 번호가 유지됐는지, 재사용됐는지 |
| W2 | `w02`에 폴더 밖(`<폴더>-outside`)을 가리키는 junction(`mklink /J`)과 디렉터리 symlink를 만들고, 훑는 도중 마지막 이름을 symlink로 바꿔치기 | 폴더 밖 표식이 든 원본이 0건이면 통과, 있으면 실패 | 건너뜀 사유가 목록에 남았는지 |
| W3 | 클라우드 동기화 폴더의 "온라인 전용" 파일을 승인 위치에 둠 | (판정 없음) | 읽기가 내려받기를 일으켰는지, 걸린 시간, 사유 |
| W4 | UNC 경로 승인 시도, 드라이브 문자에 붙인 네트워크 드라이브 승인 시도 | (판정 없음) | 전자는 거부됐는지, 후자는 어떻게 되었는지 |
| W5 | `w05`의 260자 넘는 경로, 끝이 점·공백인 이름, 예약 이름(`CON`) | (판정 없음) | 건너뛰거나 읽었는지, 앱이 죽지 않았는지 |
| W6 | 잇단 저장, 폴더 통째 이동, 절전·최대 절전 복귀 뒤 | (판정 없음) | 신호의 수와 누락, 다음 훑기 뒤 상태가 디스크와 같은지 |
| W7 | `w07`의 `Case.md`를 대소문자만 바꿔 이름 바꾸기, 한글 이름(NFC·NFD) 두 파일 | (판정 없음) | 같은 원본으로 남는지 |
| W8 | Office로 `w08`의 문서를 연 채 훑기, `~$` 파일 | (판정 없음) | `locked`로 건너뛰고 닫은 뒤 다음 훑기에 들어왔는지 |
| W9 | 설치본에서 정규화 작업자를 시험하는 두 재현 입력(I02B-C49의 입력)을 승인 폴더에 둠 | (판정 없음) | 상한 안에 끊기고 백엔드가 응답했는지 |
| W10 | 선택 창, "폴더에서 보기", 외장 디스크 뽑기와 다시 꽂기 | (판정 없음) | 선택 창 없는 승인이 거부되는지, 파일이 실행되지 않는지, 뽑았을 때 삭제가 0건인지, 다시 꽂았을 때 저절로 돌아오는지 |
| W11 | 데이터 디렉터리와 userData를 대소문자만 다르게, 8.3 짧은 이름으로, `\\?\` 접두사로, junction을 거쳐 승인 시도 | (판정 없음) | 넷 다 거부되는지, `fs.realpath.native`가 돌려준 글자 |
| W12 | NTFS·exFAT·ReFS 볼륨에 폴더를 두고 승인 | (판정 없음) | 정상 파일이 `redirected`·`identity-unavailable`로 건너뛰어지지 않았는지, `(dev, ino)`가 0인 파일 시스템이 있는지 |

4. 앱을 **닫습니다**(정본에 쓰는 프로세스가 없어야 합니다).
5. `answers.json`에 사람이 본 결과를 적습니다: `{"W3": "pass", "W4": "fail"}`. 값은 `pass`, `fail`, `inconclusive`이고 적지 않은 항목은 `inconclusive`입니다. 정본에서 판정할 수 있는 항목(W1, W2)은 정본의 판정이 이깁니다.
6. 기록합니다.

```
python verification\local-files\run.py record --app "<설치 폴더>" --folder C:\pki-lf\docs --data-dir "%LOCALAPPDATA%\PKI" --out C:\pki-lf\result.json --answers C:\pki-lf\answers.json
```

## 5. 기록의 모양과 남기는 곳

`result.json`: `{ "kit", "os", "appVersion", "fileSystem", "items": { "W1": "pass" | "fail" | "inconclusive", ... } }`. 파일 이름, 경로, 글, 표식은 없습니다. 실패한 항목은 공용 저장소에 **합성 재현 형태로** 이슈를 열고(배포처의 실제 이름과 경로를 적지 않습니다), 결과 파일은 배포처 안에만 둡니다.

## 6. 알려진 한계

- 앱 버전은 `resources\app\package.json`의 `version`에서 읽습니다. 설치본의 구조가 다르면 `unknown`으로 적힙니다(이 경로는 이 저장소에서 확인하지 못했습니다).
- 파일 시스템 종류는 Windows API로 묻고, 묻지 못하면 `unknown`입니다.
- W1·W2 말고는 정본에서 판정하지 못하고 사람이 답합니다. 판정하는 두 항목도 Windows에서 돌려 본 적이 없습니다.
