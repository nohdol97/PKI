# ADR 0026: 벡터 색인은 앱 코드의 전수 코사인 비교를 잠정 구현으로 하고, 세대를 옆에 만들어 한 번에 바꾼다

- 날짜: 2026-11-24 / 상태: **잠정 — R07·배포처 검증 대기**(실제 모델·실제 크기에서의 시간은 재지 않았다)
- 관련: [H01-C3 spec](../specs/2026-11-24-H01-C3-vector-index.md)(H01C3-R1~R11, D1~D12), 이슈 #32·#37(R07), [ADR 0004](0004-embedded-storage.md)(벡터는 어댑터 뒤, sqlite-vec 후보), [ADR 0006](0006-embedding.md)(모델 교체는 색인을 통째로 다시 만듦), [ADR 0025](0025-retrieval-strategies.md)(`vector` 전략은 기본 끔), ARCHITECTURE 3.2·4·5.4절

## 맥락

`vector` 전략은 X01이 만들었지만 제품이 묶는 색인은 모든 호출을 거절하는 `EmptyVectorIndex`였고, 문서를 embedding해 넣는 길이 없었다. 규격의 `reset`은 먼저 다 버리고 다시 만드는 모양이라 모델을 바꾸다 실패하면 이전 색인도 없었다. ADR 0004는 "첫 색인 작업 전에 R07이 실제 구현을 고른다"고 적었고, ARCHITECTURE 3.2절은 "벡터 점수 계산"을 엔진의 일로 둔다. R07(#37)은 아직 닫히지 않았다.

## 결정

- **잠정 구현은 앱 코드의 전수 코사인 비교다.** `SqliteVectorIndex`가 데이터 폴더의 `vectors/index.sqlite`(정본과 다른 파일, 같은 드라이버)에 벡터를 두고, 검색은 활성 세대의 벡터를 모두 읽어 점수순으로 줄 세운다. 새 네이티브 의존성이 없다. ADR 0004가 sqlite-vec의 교체안으로 남긴 것(가정 A08)을 R07보다 먼저 잠정으로 쓰는 것이며, 3.2절의 "벡터 점수 계산은 엔진의 일"이라는 선을 이 구현에 한해 넘는다. R07이 다른 구현을 고르면 `storage/src/adapters`의 파일 하나와 조립 한 줄을 바꾸고, 계약 시험이 같은 동작을 지킨다.
- **벡터는 정본과 다른 파일에 두고 백업에서 뺀다.** 백업은 정본 파일을 통째로 뜨므로 정본의 테이블로 두면 투영이 백업에 실린다(H01-R2). 복원 뒤에는 기존 재구축 요청이 다시 만든다. 파일의 스키마가 빌드와 다르면 지우고 빈 색인으로 시작한다.
- **규격이 세대(generation)를 안다.** `reset`을 없애고 `beginRebuild(space)`가 돌려주는 손잡이(`refs`, `upsert`, `activate`, `discard`)로 옆에 만든다. `activate`는 한 트랜잭션에서 ① 만드는 세대의 ref 집합이 기대한 집합과 같은지 보고 ② 활성으로 바꾸고 ③ 이전 활성 세대의 행을 지우고 ④ 반영 순번을 적는다. 다르면 아무것도 바꾸지 않는다. `remove`는 모든 세대에서 지운다(지운 원본의 벡터가 어느 세대에도 남지 않게). 다시 열 때 만들던 세대는 버리고 활성 세대는 그대로 답한다.
- **교체는 따로 만든 길이 아니라 `projection-rebuild` 작업이다.** 작업은 지금 embedder의 공간으로 세대를 만들고, 대상 집합(원본마다 최신 version)의 글(`제목\n본문`)을 묶음마다 embedding해 넣고, 정본에 더는 없는 ref를 지우고 빠진 것을 채워 ref 집합이 같아지면 전환한다. 실패·중단·꺼짐 뒤에는 이전 세대만 남는다. 시작할 때의 비교는 embedding하지 않고, 뒤처짐·낡음 표시·활성 세대 없음·공간 다름을 보면 작업을 요청한다.
- **복원이 적용된 시작은 벡터 파일을 지우고 다시 만든다.** 복원은 정본 파일만 바꾸므로 이전 세대의 벡터와 순번 표시는 복원 전 시간선의 것이다. 남겨 두면 복원 뒤의 삭제 작업이 그 벡터를 이름 짓지 못하거나 낡은 순번으로 거부당해, 지운 원본의 벡터가 디스크에 남는다(낡음 표시는 답하는 것만 막는다).
- **문서 embedding은 전송 정책을 지난다.** 재구축과 새 version 통지의 embedding은 `embedWithinPolicy`와 `denyExternalEmbedding`을 거치므로 `egress`가 `local`이 아닌 embedder는 불리지 않는다.
- **켜는 것은 옵션(`bootBackend`의 `vectorIndexing`)이고 기본은 꺼짐이다.** 꺼져 있으면 `EmptyVectorIndex`가 묶이고 `vector` 전략은 기본 목록 밖이며 `vectors/`는 시작할 때 지운다. 읽는 쪽이 보는 색인은 `status`만 덧씌운 것이다(낡음 표시 → `rebuilding`, 활성 세대의 공간이 묶인 embedder와 다름 → `unavailable`).

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 벡터를 정본 SQLite의 테이블로 | 백업이 벡터를 싣게 되고(H01-R2와 어긋남) 정본 마이그레이션과 복원의 스키마 대조를 건드린다. ARCHITECTURE 4절도 별도 파일로 적는다 |
| `reset`을 남기고 세대 메서드를 더하기 | 다시 만드는 길이 둘이 된다 |
| 새 작업 종류·API로 교체를 시작 | 재구축 작업이 이미 요청·중복 방지·재시도·화면 문구를 갖고 있다 |
| 만드는 동안 삭제를 막기 | 삭제가 색인을 기다리면 안 된다 |
| sqlite-vec를 지금 넣기 | R07의 일이고 위험 "높음"이다(ADR 0004) |

## 결과

- 교체 중(공간이 바뀐 동안)에는 질의를 옛 모델로 embedding할 수 없어 `vector` 전략이 `unavailable`이다. 다른 전략은 그대로 답하고, 이전 세대는 지워지지 않아 embedder를 되돌리면 다시 만들지 않고 바로 답한다. 교체 중에도 벡터 검색을 잇으려면 embedder 둘을 함께 묶는 구조가 필요하다.
- 원본 version 하나에 벡터 하나다. 긴 문서는 모델의 한도에서 잘린다(조각 나누기는 3.2절이 엔진의 일로 둔다).
- 만들던 세대는 이어 만들지 않는다. 재구축 작업의 실행 한도(60분) 안에 끝나지 않는 코퍼스는 전환하지 못한다. 실제 크기의 시간은 재지 않았다.
- 색인 파일은 암호화하지 않는다(ADR 0010의 현재 결정과 같다). 지운 자리는 드라이버의 `secure_delete`가 덮는다.
- 질의를 embedding하는 자리는 `backend/src/ask.ts`에서 `embedWithinPolicy`를 지난다(RVF-R1). 외부 embedder는 호출되지 않고 `vector`가 `unavailable`이다.
- 배포처 S39가 옵션과 `askStrategies`를 함께 켜고 실제 모델로 만들기·찾기·삭제 뒤 부재·교체와 시간을 확인한다.
