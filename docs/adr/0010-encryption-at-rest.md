# ADR 0010: 저장 데이터 암호화의 범위와 키 보관

- 날짜: 2026-11-21 / 상태: **잠정 — 배포처 검증 대기**(그리고 사용자 확인이 필요한 결정이 하나 있다. 아래 "미해결")
- 관련: 원 설계 17절, 이슈 #15 R06-C3, 이슈 #16 V01-C5, [ARCHITECTURE 4절·8절](../ARCHITECTURE.md), 가정 A16, A19

## 맥락

원 설계 17절은 "OS 사용자별 데이터 격리", "로컬 데이터 암호화", "OS Credential Store 활용", "로그 내 민감 정보 제거"를 초기부터 고려하라고 한다. R06-C3은 암호화 대상, 키 저장, 백업 암호화, 임시 파일과 로그를 결정하라고 한다.

무엇으로부터 지키는지부터 나눈다.

| 위협 | 막는 수단 |
|---|---|
| 같은 PC의 다른 OS 사용자 | OS 사용자별 데이터 디렉터리와 파일 권한 |
| PC나 디스크를 잃어버림 | OS의 디스크 암호화. 또는 DB 파일 자체의 암호화 |
| 백업 파일이 다른 곳으로 복사됨 | 백업 파일 암호화 |
| 사용자 권한으로 도는 악성 프로그램 | 위 수단으로는 막지 못한다 |

정본 SQLite 파일을 통째로 암호화하려면 암호화를 지원하는 SQLite 빌드가 필요하다. **그런 구성요소는 [OSS_EVALUATION](../OSS_EVALUATION.md)에서 평가하지 않았다.** 평가하지 않은 네이티브 구성요소를 여기서 고르지 않는다. 본문 열만 앱에서 암호화하는 방법은 키워드 색인과 벡터에 내용이 그대로 남아 보호되는 것처럼 보이기만 한다.

## 결정

| 대상 | Phase 1 | 뒤 단계 |
|---|---|---|
| 비밀 값(API 키 등) | **OS 자격 증명 저장소에만** 둔다. SQLite, 설정 파일, 로그, 환경 파일에 쓰지 않는다. 저장소를 쓸 수 없으면 평문으로 넘어가지 않고 "사용 불가"로 표시한다 | 같음 |
| 정본 SQLite 파일 | **파일 단위 암호화 없음.** OS 사용자별 디렉터리에 두고, 화면의 설정에 "데이터베이스 암호화: 적용 안 됨"을 그대로 보인다 | H01(#32) 전에 암호화 SQLite 드라이버를 조사·평가해 이 ADR을 고친다. SQL 드라이버 포트([ADR 0004](0004-embedded-storage.md)) 덕분에 상위 코드는 바뀌지 않는다 |
| 벡터 색인, 모델 캐시 | 암호화 없음. 벡터는 투영이고 모델은 공개 파일이다 | 정본과 같은 방식을 벡터에 적용할지 H01에서 정한다 |
| 백업 | Phase 1에 백업 기능 없음 | **백업 파일은 반드시 암호화한다.** 다른 PC에서 복원할 수 있어야 하므로 키는 사용자가 정한 암호구에서 만든다. 방식은 H01 spec |
| 임시 파일 | 가져온 내용을 임시 파일로 쓰지 않는다. CLI에는 stdin으로 준다. CLI가 요구하는 결과 파일은 작업마다 만든 임시 디렉터리에 두고 끝나면 지운다 | 같음 |
| 로그 | 원문, 프롬프트, 응답 본문, 비밀 값을 기록하지 않는다 | 같음 |

**실제 업무 데이터 조건**: 정본 SQLite의 파일 단위 암호화가 들어가기 전에는, 배포처가 OS 디스크 암호화 같은 보호를 확인한 PC에서만 실제 업무 데이터를 넣는다([site-setup.md](../site-setup.md) S11). 공용 저장소의 개발과 테스트는 합성 데이터만 쓴다.

OS 자격 증명 저장소는 Electron 쉘이 중개한다. 쓸 구체적 API는 V01에서 정하며 OSS_EVALUATION의 평가 범위 밖이다. 배포처 Windows에서 쓸 수 있는지는 가정 A16이다. 브라우저 개발 환경에는 쉘이 없으므로 비밀 값을 환경 변수로만 읽고 저장하지 않는다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 지금 암호화 SQLite 드라이버를 골라 넣음 | 평가하지 않은 네이티브 구성요소다. Windows 바이너리, 라이선스, 유지보수를 모른다 |
| 본문 열만 앱에서 암호화 | 키워드 색인과 벡터에 내용이 남는다. 검색을 포기하지 않는 한 보호가 되지 않는다 |
| 비밀 값을 암호화해 SQLite에 저장 | 키를 어디 둘지의 문제가 그대로 남는다. OS 자격 증명 저장소가 그 답이다 |

## 결과

- V01-C5의 "로컬 데이터 암호화"는 이 표의 Phase 1 칸만큼만 충족된다. **정본 파일 암호화는 Phase 1에 없다**는 점을 V01 spec과 PR에 그대로 적는다.
- 디스크 암호화가 없는 PC를 잃어버리면 정본 파일을 읽을 수 있다.

## 미해결

Phase 1을 "정본 SQLite 평문 + OS 수준 보호"로 시작하는 것을 사용자가 받아들이는지 확인이 필요하다. 받아들이지 않으면 암호화 SQLite 드라이버 조사를 V01의 선행 작업으로 올린다.
