# ADR 0006: Embedding — 별도 계약, bge-m3를 Node에서, 최초 사용 시 준비

- 날짜: 2026-11-21 / 상태: **잠정 — 배포처 검증 대기**
- 관련: 원 설계 4절 "Embedding", [ARCHITECTURE 5.2절](../ARCHITECTURE.md), [OSS_EVALUATION 4.5절·4.7절·4.8절](../OSS_EVALUATION.md), 가정 A11, A12

## 맥락

원 설계는 embedding을 생성형 LLM과 따로 구성하고, 기본값을 로컬 CPU에서 도는 다국어 모델로 하며, 모델 교체에 따른 재색인을 지원하라고 한다. 조사 결과(실행 없음):

- BAAI/bge-m3는 MIT이고 커뮤니티 ONNX(int8)가 568 MB다. 한국어 점수는 KURE 팀 자체 보고 표에서 0.598/0.646이며 독립 재현은 없다(4.5절, 4.7절 10번).
- Transformers.js는 Apache-2.0이고 `onnxruntime-node` 1.30.0에 고정되어 있다. Electron 관련 열린 이슈(#895, #1240, #487)와 네이티브 `sharp` 의존이 있어 위험 "중간"이다(4.5절).
- 처음 실행할 때 모델을 내려받는 방식은 "오프라인 설치 파일 하나"를 깨뜨린다(4.7절 11번).

## 결정

- `EmbeddingProvider`는 LLM Provider와 **분리된 계약**이다. 로컬에서 계산하므로 외부 전송이 아니다.
- 잠정 기본 모델은 **BAAI/bge-m3(int8 ONNX)**, 런타임은 **Node의 Transformers.js**다. Python 사이드카를 쓰지 않는다.
- 모델 파일은 **설치 파일에 넣지 않는다**(크기). 처음 쓸 때 준비하고 로컬 캐시에 둔다. 준비 방법은 둘이다: ① 사용자가 승인한 내려받기 ② 미리 받아 둔 **로컬 팩**을 폴더에서 가져오기. 준비가 끝나면 네트워크 없이 동작한다.
- 모델이 없거나 준비할 수 없으면 그 상태를 화면에 보이고, **키워드 검색은 모델 없이 동작한다.**
- 모델 ID나 revision이 바뀌면 벡터 색인을 통째로 다시 만든다. 모델 갱신은 사용자가 시작하며 자동으로 바꾸지 않는다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 모델을 설치 파일에 포함 | 568 MB가 설치 파일에 더해진다. 4.7절 11번은 "설치 파일이나 설치 후 팩"을 둘 다 인정한다. 이 ADR은 뒤쪽을 택했다 |
| multilingual-e5-base(int8 279 MB) | 같은 표에서 한국어 점수가 낮다(0.545). **차선**으로 남긴다 |
| KURE-v1, BGE-m3-ko | 점수는 비슷하거나 약간 높으나 ONNX가 없어 직접 변환이 필요하다(4.8절) |
| jina-embeddings v3/v4/v5 | 비상업·연구 라이선스라 번들할 수 없다(4.7절 1번) |
| EmbeddingGemma | Gemma 이용 조건 전달과 Notice 파일이 필요한 조건부. 기본값으로 쓰지 않는다(4.7절 2번) |
| fastembed(Python) + onnxruntime | Python 사이드카가 필요해진다. Transformers.js가 Electron에서 안 될 때의 차선 런타임(4.8절) |

## 결과

- **원 설계와의 긴장**: "설치 파일 하나만 설치하면 사용"(1절)에 대해, embedding은 설치 뒤 한 번의 준비 단계가 더 있다. 준비 전에도 가져오기·키워드 검색·탐색은 된다.
- 배포처가 외부 모델 저장소 접근을 막으면 로컬 팩 반입이 유일한 경로다(A12). 반입 절차는 [site-setup.md](../site-setup.md)에 있다.
- 로컬 팩의 정확한 형식(폴더 구조, 무결성 확인용 해시 목록)은 V01 spec에서 정한다.
- bge-m3가 Electron 설치본 안에서 CPU로 돌고 속도·메모리가 받아들일 만한지는 미검증이다(A11).
- 번들·반입하는 모델의 라이선스 고지는 모델과 함께 둔다. 모델 학습 데이터의 라이선스는 조사에서 확인하지 않았다(OSS_EVALUATION 8절).
