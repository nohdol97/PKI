# ADR 0006: Embedding — 별도 계약, bge-m3를 Node에서, 설치 뒤 준비

- 날짜: 2026-11-21 / 상태: **잠정 — 배포처 검증 대기**. 모델을 설치 파일에 넣지 않는다는 부분은 **사용자 확인 대기**다
- 관련: 원 설계 1절·4절 "Embedding", [ARCHITECTURE "사용자 확인이 필요한 결정"·5.2절](../ARCHITECTURE.md), [OSS_EVALUATION 4.5절·4.7절·4.8절](../OSS_EVALUATION.md), 가정 A11, A12

## 맥락

원 설계는 embedding을 생성형 LLM과 따로 구성하고, 기본값을 로컬 CPU에서 도는 다국어 모델로 하며, 모델 교체에 따른 재색인을 지원하라고 한다. 조사 결과(실행 없음):

- BAAI/bge-m3는 MIT이고 커뮤니티 ONNX(int8)가 568 MB다. 한국어 점수는 KURE 팀 자체 보고 표에서 0.598/0.646이며 독립 재현은 없다(4.5절, 4.7절 10번).
- Transformers.js는 Apache-2.0이고 `onnxruntime-node` 1.30.0에 고정되어 있다. Electron 관련 열린 이슈(#895, #1240, #487)와 네이티브 `sharp` 의존이 있어 위험 "중간"이다(4.5절).
- **처음 실행할 때 모델을 내려받는 방식은 "오프라인 설치 파일 하나"를 깨뜨린다. 가중치를 설치 파일이나 설치 후 팩에 미리 넣어야 한다**(4.7절 11번).

## 결정

- `EmbeddingProvider`는 LLM Provider와 **분리된 계약**이다. 구현마다 `egress`가 `'local'`인지 `'external'`인지 밝힌다. 공용 저장소의 구현은 로컬 계산이다. 외부 서비스를 부르는 구현은 LLM 호출과 같은 동의·전송 정책을 지난다([ADR 0014](0014-egress-policy-and-consent.md)).
- 잠정 기본 모델은 **BAAI/bge-m3(int8 ONNX)**, 런타임은 **Node의 Transformers.js**다. Python 사이드카를 쓰지 않는다.
- 모델 파일은 **설치 파일에 넣지 않는다**(크기). 설치 뒤에 준비하며 방법은 둘이다.
  - **로컬 팩**: 미리 받아 둔 모델 폴더를 가져온다. 네트워크가 필요 없다. 조사 4.7절 11번이 말하는 "설치 후 팩"이 이것이며, **오프라인 환경에서 쓸 수 있는 유일한 경로**다.
  - **내려받기**: 사용자가 승인하면 모델 저장소에서 받는다. 네트워크가 있을 때의 편의 경로다. 이 경로만으로는 4.7절 11번의 문제가 그대로 남는다.
- 어느 쪽도 기본으로 자동 실행하지 않는다. 사용자가 고르기 전의 상태는 "모델 없음"이다.
- **무결성**: 쓰는 모델의 revision과 파일별 해시를 제품의 빌드 자원에 고정해 둔다. 로컬 팩이든 내려받기든 해시가 모두 맞을 때만 "준비됨"이 된다. 맞지 않으면 그 파일을 쓰지 않고 상태를 알린다. 고정할 revision과 해시 값은 V01-T14에서 정해 기록한다(커뮤니티 ONNX 저장소의 특정 revision을 이 문서 작성 때는 고르지 않았다). **(V01-T14에서 정함)** `onnx-community/bge-m3-ONNX`의 commit `25b9af8e87a38eb120cfe87125383677b9cd309e`, int8 ONNX와 토크나이저·설정 파일 4개의 크기와 SHA-256을 `providers/src/adapters/bge-m3.ts`에 고정했다. 설치 방식과 실제 모델 왕복의 기록은 [V01 spec "T14이 넘기는 것"](../specs/2026-11-21-V01-vertical-skeleton.md)에 있다.
- 모델이 없거나 준비할 수 없으면 그 상태를 화면에 보이고, **키워드 검색은 모델 없이 동작한다.**
- 모델 ID나 revision이 바뀌면 벡터 색인을 통째로 다시 만든다. 모델 갱신은 제품 버전과 함께 고정 값이 바뀔 때만 일어나며 자동으로 바꾸지 않는다.

## 원 설계와의 긴장

"최종 사용자는 설치 파일 하나만 설치하면 사용할 수 있어야 한다"(1절)에 대해, embedding은 설치 뒤 준비 단계가 한 번 더 있다. 준비 전에도 가져오기·키워드 검색·탐색은 된다. 설치 파일에 568 MB를 더해 이 단계를 없앨지는 사용자가 정한다. 번복되면 모델 준비 방식(V01-T14)과 패키징 구성을 다시 한다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 모델을 설치 파일에 포함 | 568 MB가 설치 파일에 더해진다. 4.7절 11번이 인정하는 두 방법 중 하나이므로 틀린 선택은 아니며, 위 "긴장"의 사용자 확인 대상이다 |
| 처음 쓸 때 자동으로 내려받음 | 네트워크가 없으면 실패하고, 사용자 모르게 외부에 접속한다 |
| multilingual-e5-base(int8 279 MB) | 같은 표에서 한국어 점수가 낮다(0.545). **차선**으로 남긴다 |
| KURE-v1, BGE-m3-ko | 점수는 비슷하거나 약간 높으나 ONNX가 없어 직접 변환이 필요하다(4.8절) |
| jina-embeddings v3/v4/v5 | 비상업·연구 라이선스라 번들할 수 없다(4.7절 1번) |
| EmbeddingGemma | Gemma 이용 조건 전달과 Notice 파일이 필요한 조건부. 기본값으로 쓰지 않는다(4.7절 2번) |
| fastembed(Python) + onnxruntime | Python 사이드카가 필요해진다. Transformers.js가 Electron에서 안 될 때의 차선 런타임(4.8절) |

## 결과

- 배포처가 외부 모델 저장소 접근을 막으면 로컬 팩 반입이 유일한 경로다(A12). 반입 절차는 [site-setup.md](../site-setup.md)에 있다.
- 로컬 팩의 형식은 "고정된 파일 목록과 해시에 맞는 폴더"다. 그 밖의 묶음 형식을 따로 만들지 않는다.
- bge-m3가 Electron 설치본 안에서 CPU로 돌고 속도·메모리가 받아들일 만한지는 미검증이다(A11).
- 번들·반입하는 모델의 라이선스 고지는 모델과 함께 둔다. 모델 학습 데이터의 라이선스는 조사에서 확인하지 않았다(OSS_EVALUATION 8절).
