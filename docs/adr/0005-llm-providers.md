# ADR 0005: LLM Provider — CLI 2종과 API 키 경로, 백그라운드 CLI는 기본 OFF

- 날짜: 2026-11-21 / 상태: **잠정 — 배포처 검증 대기**
- 관련: 원 설계 4절, [ARCHITECTURE 3.1절·5.1절](../ARCHITECTURE.md), [CLI Provider 조사](../research/2026-11-21-cli-provider-terms-and-isolation.md), 가정 A01~A06

## 맥락

원 설계 4절은 사용자 PC에 이미 로그인된 Claude Code 또는 Codex CLI를 자동 탐색해 쓰고, API 키 입력을 기본 요구사항으로 하지 않는다. 사용자는 배포 환경에서 두 CLI를 쓸 수 있다고 확인했다.

조사 결과는 두 갈래다(전부 문서 조사이며 모델 호출을 한 번도 실행하지 않았다).

- **허용 여부**: Anthropic 문구는 제3자 제품이 구독 자격 증명으로 요청을 보내는 것에 금지 쪽으로 읽히고, OpenAI는 프로그램 사용에 API 키를 권장한다. 판정은 둘 다 "모호"다(조사 3절). 이 ADR은 벤더가 허용한다고 말하지 않는다.
- **격리 여부**: 문서상 플래그는 있으나 전부 미실행이다. Claude의 OS 샌드박스는 네이티브 Windows에서 동작하지 않고, Codex의 `read-only`는 파일 읽기를 막지 않으며, 두 CLI 모두 Windows 취소 계약이 문서에 없다(조사 2절 Q2-C2, Q2-X1, Q2-X2).

## 결정

1. `ClaudeCodeProvider`와 `CodexProvider`를 원 설계대로 구현한다. 둘 다 있으면 사용자가 기본값을 고른다.
2. **API 키로 쓰는 OpenAI 호환 Provider를 선택 사항이 아닌 정식 경로로 함께 구현한다.** 구독 경로가 막혀도 제품이 동작해야 하기 때문이다(조사 9절의 선택지 B). API 키 입력은 여전히 기본 요구사항이 아니다. 사용자가 이 경로를 고를 때만 요구한다.
3. `LocalModelProvider`는 계약만 두고 "미구현"을 돌려준다.
4. **CLI Provider의 백그라운드 자동 실행은 기본 OFF**다. 배포처에서 격리를 검증한 CLI 버전·설정 조합이 제품의 목록에 있고 사용자가 켰을 때만 실행한다.
5. 격리 검증 전에도 **대화형 호출**(사용자가 화면에서 직접 누른 한 번)과 test double은 허용한다. 대화형 호출은 언제나 최소 권한 인자 배열, 빈 임시 디렉터리, 최소 환경 변수로 실행하고, "격리 미검증" 표시와 사용자 확인을 거친다.
6. **전송 정책과 동의는 모든 Provider에 적용한다**([ADR 0014](0014-egress-policy-and-consent.md)). 한 Provider가 막혔을 때 다른 Provider로 몰래 넘어가지 않는다.
7. 제품은 CLI의 로그인 파일·토큰을 읽거나 복사하거나 저장하지 않는다. 인증 상태는 CLI가 제공하는 상태 확인으로만 본다.
8. 모든 호출은 Broker를 지난다. 시간 제한, 재시도 간격, 요청 한도 대응, 동시 실행 제한, 호출 예산, 오류 복구, 본문 없는 이력을 Broker가 공통으로 처리한다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| CLI 구독만(조사 선택지 A) | 벤더 회신이 없거나 부정적이면 LLM 경로가 통째로 막힌다 |
| API 키만(선택지 C) | 원 설계의 핵심(기존 로그인 재사용)을 버린다. 사용자가 CLI 사용 가능을 확인했다 |
| 격리 검증 전 백그라운드 실행 허용 | 가져온 문서의 악성 지시가 도구·파일·MCP를 쓸 수 있는지 확인되지 않았다. 원 설계 4절도 "권한 제한을 보장할 수 없는 Provider의 백그라운드 자동 실행은 차단"한다 |
| CLI를 OpenAI 호환 서버처럼 보이게 하는 로컬 중개기(shim) | 엔진이 요구할 때만 필요하다. Phase 1에는 엔진이 없다 |

## 결과

- 구현·시험 범위가 Provider 3종으로 늘어난다.
- API 키 경로는 사용량 과금이 생길 수 있고 키 보관이 필요하다([ADR 0010](0010-encryption-at-rest.md)).
- **남는 위험**: 대화형 호출도 가져온 문서를 CLI에 넣는다. 사용자가 눌렀다는 사실이 문서를 믿을 수 있게 만들지는 않는다. 격리가 검증되기 전의 대화형 호출은 최소 권한 인자 배열이 문서대로 동작한다는 가정(A02, A03)에 기대고 있으며, 그래서 "격리 미검증"을 화면에 표시한다.
- 이슈 #16의 V01-C4 문구는 "Optional OpenAI-compatible … 미구현 상태를 명시"라고 적혀 있어 결정 2와 어긋난다. V01 spec은 OpenAI 호환을 구현 대상으로 요구하고, 이슈 문구 갱신은 미해결 질문으로 남긴다.
- 배포처에서 A01이 거짓으로 확인되면 CLI Provider를 배포처 설정으로 끈다. 코드 변경은 없다.
