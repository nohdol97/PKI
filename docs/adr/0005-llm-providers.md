# ADR 0005: LLM Provider — CLI 2종과 API 키 필수 경로, 배포 빌드는 검증된 CLI만 실행

- 날짜: 2026-11-21 / 상태: **잠정 — 배포처 검증 대기**
- 관련: 원 설계 4절, 이슈 #16 V01-C4, [ARCHITECTURE 3.1절·5.1절](../ARCHITECTURE.md), [CLI Provider 조사](../research/2026-11-21-cli-provider-terms-and-isolation.md), 가정 A01~A06, A22

## 맥락

원 설계 4절은 사용자 PC에 이미 로그인된 Claude Code 또는 Codex CLI를 자동 탐색해 쓰고, API 키 입력을 기본 요구사항으로 하지 않는다. "배포처에서 두 CLI를 쓸 수 있다"는 것은 **사용자의 진술(2026-11-21)이다. 그것을 뒷받침하는 문서는 이 저장소에 없으며** R02가 배포처에서 확인한다(A01).

조사 결과는 두 갈래다(전부 문서 조사이며 모델 호출을 한 번도 실행하지 않았다).

- **허용 여부**: Anthropic 문구는 제3자 제품이 구독 자격 증명으로 요청을 보내는 것에 금지 쪽으로 읽히고, OpenAI는 프로그램 사용에 API 키를 권장한다. 판정은 둘 다 "모호"다(조사 3절). 이 ADR은 벤더가 허용한다고 말하지 않는다.
- **격리 여부**: 문서상 플래그는 있으나 전부 미실행이다. Claude의 OS 샌드박스는 네이티브 Windows에서 동작하지 않고, Codex의 `read-only`는 파일 읽기를 막지 않으며, 두 CLI 모두 Windows 취소 계약이 문서에 없다(조사 2절 Q2-C2, Q2-X1, Q2-X2).

가져온 문서는 신뢰할 수 없는 데이터다. 사용자가 버튼을 눌렀다는 사실이 그 문서를 믿을 수 있게 만들지는 않는다. 격리가 확인되지 않은 CLI에 문서를 넣으면, 누가 호출을 시작했든 문서 안의 악성 지시가 그 PC의 파일과 도구에 닿을 수 있다.

## 결정

**Provider의 구성**

1. `ClaudeCodeProvider`와 `CodexProvider`를 원 설계대로 구현한다. 둘 다 있으면 사용자가 기본값을 고른다.
2. **API 키로 쓰는 OpenAI 호환 Provider는 필수 경로다.** 구독 로그인 재사용의 약관이 불리하게 확정되어도 제품이 동작해야 하기 때문이다(조사 9절의 선택지 B).
3. `LocalModelProvider`는 계약만 두고 "미구현"을 돌려준다.

**CLI를 실행해도 되는 경우**(표와 입력의 정의는 ARCHITECTURE 3.1절)

4. **배포 빌드는 검증된 조합 목록에 있는 CLI만 실행한다.** 목록에 없으면 사용자 호출과 백그라운드 호출을 **모두** 차단한다. 목록에 있어도 백그라운드 자동 실행은 기본 OFF다.
5. **개발 빌드**는 목록에 없는 조합을 다음을 모두 만족할 때만 실행한다: 사용자 호출이다, 입력이 전부 "합성" 등급이고 악성 변형이 아니다, 고정된 최소 권한 인자 프로필을 쓴다, "격리 미검증"을 표시한다, 그 호출 한 번에 대해 사용자가 확인했다.
6. **판정에 쓰는 값은 호출하는 쪽이 넘길 수 없다.**
   - 빌드 종류는 빌드할 때 코드에 박히는 값 하나에서만 읽는다. 값이 없거나 모르는 값이면 배포 빌드다(닫힌 쪽이 기본). 배포 빌드의 산출물에는 5번의 예외 코드가 들어 있지 않다.
   - 검증된 조합 목록은 읽기 전용 빌드 자원이다. 항목은 CLI 이름, 정확한 버전 하나, OS, 인자 프로필 이름, 검증 날짜다. 버전 범위를 쓰지 않는다(조사 6절: CLI 버전이 바뀔 때마다 부정 테스트를 다시 돌려야 한다). 인자 프로필의 내용은 코드의 상수다. 사용자 데이터 폴더의 설정, 환경 변수, 설정 API로는 항목을 더할 수 없다.
   - 호출 종류는 Broker가 작업 기록으로 판정한다. 작업 실행기가 꺼낸 작업에서 나온 호출은 백그라운드다. 가져오기 버튼으로 등록된 추출도 백그라운드다.
   - 데이터 등급은 Broker가 정본에서 계산한다. "합성"은 내용 해시가 빌드할 때 만든 합성 목록에 있을 때만 붙는다.
7. **test double은 테스트 빌드에만 있다.** 배포 빌드와 개발 빌드에는 가짜 Provider가 들어 있지 않다. 가짜 CLI도 같은 판정을 지나며, 테스트 빌드의 목록 자원에 그 버전이 들어 있을 뿐이다.
8. **판정 없이 실행하는 CLI 명령은 둘뿐이다**: 버전 조회와 로그인 상태 조회. 고정된 인자, 입력 없음, 문서 내용 없음, 빈 임시 디렉터리, 최소 환경 변수, 시간 제한. 연결 시험처럼 모델을 부르는 것은 전부 판정을 지난다. Codex의 로그인 상태 명령은 조사 문서에 있고 Claude Code의 것은 없다(A22). 없으면 인증 상태를 "알 수 없음"으로 둔다.

**공통**

9. **동의와 전송 정책은 모든 Provider에 적용한다**([ADR 0014](0014-egress-policy-and-consent.md)). 한 Provider가 막혔을 때 다른 Provider로 몰래 넘어가지 않는다.
10. 제품은 CLI의 로그인 파일·토큰을 읽거나 복사하거나 저장하지 않는다.
11. 모든 호출은 Broker를 지난다. 시간 제한, 재시도 간격, 요청 한도 대응, 동시 실행 제한, 호출 예산, 오류 복구, 본문 없는 이력을 Broker가 공통으로 처리한다.
12. CLI가 없거나 로그인되어 있지 않으면 설치와 로그인 방법을 안내하고, LLM이 필요 없는 기능은 계속 쓸 수 있다(원 설계 4절).

## 원 설계와의 긴장

원 설계 4절은 "별도의 API Key 입력을 기본 요구사항으로 하지 않는다"고 한다. 이 결정에서 API 키 입력은 사용자가 그 경로를 고를 때만 요구되므로 글자로는 어긋나지 않는다. 그러나 **실제로는 어긋난다**: 공용 저장소의 배포 빌드는 검증된 조합 목록이 비어 있어 CLI를 전혀 실행하지 않으므로, 배포처가 R02를 끝내기 전까지 설치본에서 LLM을 쓰려면 API 키가 **유일한** 길이다. 격리가 확인되지 않은 CLI를 설치본에서 돌리지 않기 위해 받아들인 비용이다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| CLI 구독만(조사 선택지 A) | 벤더 회신이 없거나 부정적이면 LLM 경로가 통째로 막힌다 |
| API 키만(선택지 C) | 원 설계의 핵심(기존 로그인 재사용)을 버린다 |
| 배포 빌드에서 검증 전에도 사용자가 누른 호출은 경고와 함께 허용 | 이 ADR의 초안이었다. 가져온 문서가 격리가 확인되지 않은 CLI에 들어가는 것은 누가 시작했든 같다. 경고는 격리를 대신하지 못한다 |
| 개발 빌드에서도 전부 차단 | 배포처 검증 전에 Provider 구현을 실제 CLI로 한 번도 돌려 볼 수 없게 된다 |
| 빌드 종류를 실행 환경(환경 변수, 패키지 여부 조회)에서 읽음 | 실행하는 쪽이 값을 바꿀 수 있다. 판정의 기준이 될 수 없다 |
| 검증된 조합 목록을 사용자 설정으로 둠 | 설정을 쓸 수 있는 누구나 항목을 더해 판정을 통과시킬 수 있다 |
| 요청에 등급과 호출 종류를 실어 보냄 | 부르는 코드나 가져온 레코드가 "합성", "사용자 호출"이라고 적으면 통과한다 |
| CLI를 OpenAI 호환 서버처럼 보이게 하는 로컬 중개기(shim) | 엔진이 요구할 때만 필요하다. Phase 1에는 엔진이 없다 |

## 결과

- 포크가 목록을 채우려면 `site/config/`의 목록 자원을 고치고 **다시 빌드**해야 한다. CLI가 스스로 버전을 올리면 목록의 정확한 버전과 맞지 않게 되어 그 CLI는 다시 막힌다. 번거롭지만 검증하지 않은 버전이 돌지 않는다는 뜻이다.
- **개발 빌드의 예외가 남기는 위험**: 격리가 확인되지 않은 CLI가 개발자의 PC에서 돈다. 입력이 합성이라 새어 나갈 업무 데이터는 없지만, CLI가 도구를 쓸 수 있다면 그 PC의 다른 파일에 닿을 수 있다. 줄이는 장치는 입력을 저장소에 든 악성이 아닌 합성 자료로 한정하는 것, 고정된 최소 권한 인자, 호출마다의 확인이다. Phase 1에서 이 예외로 나가는 호출은 설정 화면의 연결 시험 하나이고 그 입력은 고정된 무해한 자료다. 이 예외는 격리 검증의 증거가 아니며, 벤더가 그 호출을 허용하는지와도 무관하다(A01은 미확인이다).
- 가져오기로 등록된 추출은 백그라운드이므로, 개발 빌드에서 검증되지 않은 CLI로는 V02의 추출 흐름을 돌릴 수 없다. 그 흐름의 실제 Provider 실행은 API 키 Provider나 검증된 조합으로 한다.
- 구현·시험 범위가 Provider 3종으로 늘어난다. API 키 경로는 사용량 과금이 생길 수 있고 키 보관이 필요하다([ADR 0010](0010-encryption-at-rest.md)).
- 배포처에서 A01이 거짓으로 확인되면 CLI Provider를 배포처 설정으로 끈다. 코드 변경은 없다.
