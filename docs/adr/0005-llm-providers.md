# ADR 0005: LLM Provider — CLI 2종과 API 키 필수 경로, 배포 빌드는 검증된 CLI만 실행

- 날짜: 2026-11-21 / 상태: **잠정 — 배포처 검증 대기**
- 관련: 원 설계 4절, 이슈 #16 V01-C4, [ARCHITECTURE 3.1절·5.1절](../ARCHITECTURE.md), [CLI Provider 조사](../research/2026-11-21-cli-provider-terms-and-isolation.md), 가정 A01~A06

## 맥락

원 설계 4절은 사용자 PC에 이미 로그인된 Claude Code 또는 Codex CLI를 자동 탐색해 쓰고, API 키 입력을 기본 요구사항으로 하지 않는다. 사용자는 배포 환경에서 두 CLI를 쓸 수 있다고 확인했다.

조사 결과는 두 갈래다(전부 문서 조사이며 모델 호출을 한 번도 실행하지 않았다).

- **허용 여부**: Anthropic 문구는 제3자 제품이 구독 자격 증명으로 요청을 보내는 것에 금지 쪽으로 읽히고, OpenAI는 프로그램 사용에 API 키를 권장한다. 판정은 둘 다 "모호"다(조사 3절). 이 ADR은 벤더가 허용한다고 말하지 않는다.
- **격리 여부**: 문서상 플래그는 있으나 전부 미실행이다. Claude의 OS 샌드박스는 네이티브 Windows에서 동작하지 않고, Codex의 `read-only`는 파일 읽기를 막지 않으며, 두 CLI 모두 Windows 취소 계약이 문서에 없다(조사 2절 Q2-C2, Q2-X1, Q2-X2).

가져온 문서는 신뢰할 수 없는 데이터다. 사용자가 버튼을 눌렀다는 사실이 그 문서를 믿을 수 있게 만들지는 않는다. 격리가 확인되지 않은 CLI에 문서를 넣으면, 누가 호출을 시작했든 문서 안의 악성 지시가 파일과 도구에 닿을 수 있다.

## 결정

1. `ClaudeCodeProvider`와 `CodexProvider`를 원 설계대로 구현한다. 둘 다 있으면 사용자가 기본값을 고른다.
2. **API 키로 쓰는 OpenAI 호환 Provider는 필수 경로다.** 구독 로그인 재사용의 약관이 불리하게 확정되어도 제품이 동작해야 하기 때문이다(조사 9절의 선택지 B). API 키 입력은 여전히 기본 요구사항이 아니다. 사용자가 이 경로를 고를 때만 요구한다.
3. `LocalModelProvider`는 계약만 두고 "미구현"을 돌려준다.
4. **배포 빌드는 격리 검증(R02)을 통과한 CLI 버전과 인자 프로필로만 CLI를 실행한다.** 검증된 조합 목록에 없으면 사용자가 직접 누른 호출과 백그라운드 자동 호출을 **모두** 차단한다.
5. 목록에 있는 조합이라도 **백그라운드 자동 실행은 기본 OFF**다. 사용자가 켰을 때만 실행한다.
6. **개발 모드**에서는 목록에 없는 조합을 **합성 데이터에 한해** 호출할 수 있다. 사용자가 직접 시작한 호출이어야 하고, 최소 권한 인자 배열을 쓰며, "격리 미검증"을 표시하고, 명시적 확인을 받는다. 개발 모드인지는 빌드할 때 정해지며 실행 중 설정이나 환경 변수로 바꿀 수 없다. "합성"은 테스트 Connector와 `fixtures/` 가져오기만 붙일 수 있는 데이터 등급이다.
7. **전송 정책과 동의는 모든 Provider에 적용한다**([ADR 0014](0014-egress-policy-and-consent.md)). 한 Provider가 막혔을 때 다른 Provider로 몰래 넘어가지 않는다.
8. 제품은 CLI의 로그인 파일·토큰을 읽거나 복사하거나 저장하지 않는다. 인증 상태는 CLI가 제공하는 상태 확인으로만 본다.
9. 모든 호출은 Broker를 지난다. 시간 제한, 재시도 간격, 요청 한도 대응, 동시 실행 제한, 호출 예산, 오류 복구, 본문 없는 이력을 Broker가 공통으로 처리한다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| CLI 구독만(조사 선택지 A) | 벤더 회신이 없거나 부정적이면 LLM 경로가 통째로 막힌다 |
| API 키만(선택지 C) | 원 설계의 핵심(기존 로그인 재사용)을 버린다. 사용자가 CLI 사용 가능을 확인했다 |
| 배포 빌드에서 검증 전에도 사용자가 누른 호출은 경고와 함께 허용 | 이 ADR의 초안이었다. 가져온 문서가 격리가 확인되지 않은 CLI에 들어가는 것은 누가 시작했든 같다. 경고는 격리를 대신하지 못한다 |
| 개발 모드에서도 전부 차단 | 배포처 검증 전에 Provider 구현을 실제 CLI로 한 번도 돌려 볼 수 없게 된다. 합성 데이터로 한정하면 새어 나갈 업무 데이터가 없다 |
| CLI를 OpenAI 호환 서버처럼 보이게 하는 로컬 중개기(shim) | 엔진이 요구할 때만 필요하다. Phase 1에는 엔진이 없다 |

## 결과

- 공용 저장소의 배포 빌드는 검증된 조합 목록이 비어 있으므로 **CLI Provider를 전혀 실행하지 않는다.** 배포처가 R02를 실행해 목록을 채워야 CLI 경로가 열린다. 그때까지 배포 빌드의 LLM 경로는 API 키 Provider뿐이다.
- 구현·시험 범위가 Provider 3종으로 늘어난다.
- API 키 경로는 사용량 과금이 생길 수 있고 키 보관이 필요하다([ADR 0010](0010-encryption-at-rest.md)).
- 개발 모드의 예외는 격리 검증의 증거가 아니다. 거기서 CLI가 응답했다는 사실로 조합을 목록에 넣지 않는다. 또한 이 예외는 벤더가 그 호출을 허용하는지와 무관하다(A01은 그대로 미확인이다).
- 배포처에서 A01이 거짓으로 확인되면 CLI Provider를 배포처 설정으로 끈다. 코드 변경은 없다.
