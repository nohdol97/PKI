# ADR 0012: 공용 저장소와 배포처 포크의 소유 경계

- 날짜: 2026-11-21 / 상태: **확정**(사용자 지시. 이슈 #1 "공용 제품과 배포처 포크의 책임")
- 관련: [ownership.md](../ownership.md), [site-setup.md](../site-setup.md), 원 설계 5절

## 맥락

제품은 범용이지만 실제 메일·메신저·Wiki 수집은 배포처의 시스템과 인증에 달려 있다. 원 설계 5절도 "실제 사내 시스템 Connector 구현을 초기 개발의 전제조건으로 삼지 않는다"고 한다. 공용 저장소는 공개되어 있으므로 배포처의 주소, 계정, 정책, 데이터가 들어오면 안 된다.

## 결정

- **공용 저장소(이 저장소)**: 범용 제품 전체. Connector 규격과 계약 테스트, 로컬 import, 합성 데이터, Provider 어댑터, 지식 정책, Insight, 화면, 패키징, 품질 평가.
- **배포처 포크**: 실제 메일·메신저·Wiki 수집기, 사내 인증·권한 연동, 엔드포인트와 계정, 현장 정책 값, 배포·실행 환경 설정, 배포처 실행 검증.
- **흐름의 기본 방향은 공용 → 포크**다. 포크의 변경을 공용으로 되돌려 보내는 것은 기본 흐름에 없다.
- 포크 전용 코드와 설정은 **`site/` 디렉터리**에만 둔다. 공용 저장소는 이 디렉터리에 안내문만 두고 다른 파일을 만들지 않는다. 두 쪽이 같은 파일을 고치지 않으므로 공용 변경을 받아 갈 때 충돌이 나지 않는다.
- 배포처에 달린 값은 코드에 넣지 않고 설정으로 뺀다. 공용 저장소의 기본값은 배포처 값이 아니라 로컬에서 도는 값이다.
- 구현하지 않은 배포처 연동은 조용히 넘어가지 않는다. 실행하면 `미구현, 배포처 후속`을 알리고 실패한다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 수집기를 공용 저장소에 두고 값만 비공개 | 수집기 코드가 배포처 시스템의 API 모양을 드러낸다 |
| 포크 없이 플러그인 폴더만 | 배포처는 패키징·서명·정책 기본값도 바꿔야 한다. 포크가 그 전부를 담는다 |
| 양방향 동기화 | 배포처 내용이 공개 저장소로 새는 길이 상시로 열린다 |

## 결과

- 공용 저장소에서 범용 결함을 고칠 때는 포크의 commit을 가져오지 않고, 배포처 맥락을 뺀 채 공용에서 다시 작성한다.
- 배포처가 구현할 규격은 `packages/contracts`와 `packages/testkit`으로 제공된다. 규격이 바뀌면 포크가 깨지므로 규격에는 버전을 붙인다.
- 배포처 실행 결과를 공용 이슈에 남길 때는 합성 입력의 결과와 환경의 일반 정보만 올린다(이슈 #37 R07-C1).
