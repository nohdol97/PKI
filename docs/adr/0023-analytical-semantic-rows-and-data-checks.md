# ADR 0023: 분석 의미는 등록 행과 데이터 검사이고, 제품은 값을 계산하지 않는다

- 날짜: 2026-11-23 / 상태: **잠정 — 배포처 검증 대기**(실제 스프레드시트에서 표가 아닌 것을 표로 잡는 비율과 큰 시트의 프로파일·검사 시간은 S34에서 잰다. 그 전에는 프로파일을 꺼 둔다)
- 관련: [S03 spec](../specs/2026-11-22-S03-analytical-semantic.md)(S03-R1~R21, 잠정 결정 23·31·34), 이슈 #24, [ADR 0021](0021-semantic-registry-on-existing-rows.md), [ADR 0022](0022-entity-resolution-and-conflicts.md). **ADR 0003을 대체하지 않는다.**

## 맥락

원 설계 6.5절은 Dataset·Metric·Join 같은 분석용 지식을 요구한다. 사용자가 "월간 매출은 매출표의 금액 합계다"라고 적은 문서가 있을 때, 제품은 그 말이 실제 표와 맞는지(그 열이 있는지, 그 열로 행이 하나씩 구별되는지) 알려 줄 수 있어야 한다. 그러나 값을 계산하는 순간 제품은 질의 엔진이 된다(OSS 조사의 탈락 조건). 반대로 말만 적어 두면 틀린 계산 기준을 사용자가 믿고 승인하게 된다.

## 결정

1. **분석 의미는 등록 행이고 데이터 검사다. 제품은 값을 계산하지 않는다.** Dataset·Metric·Join은 항목, 그 속성은 사실, 이음은 관계다(새 지식 테이블 없음). 표 원본에서 얻는 것은 머리 행·열 이름·행 수와 네 가지 세는 검사(스키마·Grain·Join cardinality·집계)의 결과뿐이고, 합계나 평균 같은 값은 만들지도 저장하지도 응답에 싣지도 않는다. 검사 줄에는 센 수와 코드만 있다.
2. **어느 종류의 값이 검사를 받아야 하는지는 유형 정의의 규칙(`dataChecks`)이 정한다.** 승인·자동 승격의 입구는 사실 종류의 이름을 보지 않고 규칙을 읽는다. 그래서 S01-R4("입구는 유형 정의 밖의 이름에 기대지 않는다")가 그대로 지켜지고, 사용자가 만든 사실 종류도 같은 검사를 요구할 수 있다. 종류마다 어떤 검사가 요구·허용되는지는 값의 종류가 정한다.
3. **사용자의 승인도 검사를 지난다.** 검사가 필요한 행을 승인하려면 채워야 할 조건(Dataset이 있음, 충돌 없음, 검사 줄이 있음, 검사가 통과함)이 모두 차야 하고, 모자라면 `data-check-unmet`와 모자란 조건의 이름만 돌려준다(글·값·인용문은 싣지 않는다). 사용자가 정한 행이라는 보호(S01)는 그대로이되, 그 승인이 "표와 맞는지 확인한 것"을 대신하지는 않는다.
4. **`verified` 행을 제품이 움직이는 원인은 둘뿐이다.** 검사가 실패했을 때(`data-check-failed`)와 근거가 된 표를 잃었을 때(`data-basis-lost`). 충돌이나 "검사 줄 없음"만으로는 움직이지 않는다. 움직인 행은 `disputed`가 되고, 사용자가 정한 행도 `disputed`까지만 간다.
5. **표 프로파일은 꺼진 채로 나간다**(`analytical.profile`, 한도 `analytical.maxCells`). 프로파일은 가져온 모든 표에서 머리 행을 짐작하는 규칙이라 실제 자료에서의 오판 비율과 시간을 재기 전에는 켜지 않는다(dark launch). 켜고 끄는 길은 설정 API이고, 켜기 전에 재는 절차는 배포처 항목 S34(V02 검증 실행기의 `analytical-scenario`)다.
6. **두 단계 질의는 이 ADR이 다루지 않는다.** 한 번에 여러 걸음을 걷는 관계 탐색의 상한은 [ADR 0022](0022-entity-resolution-and-conflicts.md) 결정 4가 정한다(깊이 3). 분석용 읽기는 그 위에서 정해진 관계 몇 종류만 따라간다.

## 기각한 대안

- **제품이 값을 계산해 보여 주기**: 질의 엔진을 다시 만드는 일이다. 검증할 것은 값이 아니라 말과 표의 일치다.
- **검사 없이 말만 등록하기**: 사용자가 틀린 계산 기준을 `verified`로 올릴 수 있다.
- **사실 종류 이름(`metric.calculation` 등)으로 검사 대상을 코드에 박기**: S01-R4를 어기고 사용자가 더한 종류에는 검사가 닿지 않는다.
- **프로파일을 기본으로 켜기**: 표가 아닌 자료를 표로 잡는 비율을 모른 채 모든 가져오기에서 항목이 생긴다.

## 결과

- 마이그레이션은 더하기만 한다(`dataset_tables`, `analytical_checks`, 분석용 유형 정의 seed). 파생물 종류 `analytical-check`는 기존 정본 종류 12개 안에 들어 있다.
- 알려진 한계: 표로 보지 않은 사유는 저장하지 않으므로 S34는 사유별 수를 기록하지 못한다. 프로파일·검사 작업의 시간은 시작 시각이 없어 대기를 포함한 상한으로만 잰다. XLSX는 계약 묶음이 정규화기의 실제 출력으로 보고, 폴더에서 들이는 끝에서 끝까지의 시험은 CSV 하나다.

## 되돌리거나 다시 볼 조건

- S34의 실측에서 표가 아닌 것을 표로 잡는 비율이 높으면 프로파일의 머리 행 규칙을 고친다(이 ADR의 결정 5는 그대로).
- 사용자가 값 계산을 요구하면 별도의 ADR로 엔진 어댑터 뒤에 둔다. 이 ADR의 결정 1을 뒤집는 일이므로 사용자 확인이 필요하다.
