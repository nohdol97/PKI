# ADR 0008: 첫 slice부터 적용하는 보안 기준선

- 날짜: 2026-11-21 / 상태: **확정**(무엇을 적용할지에 대한 결정. 통제가 실제로 막는지는 V01의 허용·거부 테스트와 Phase 7 H03의 부정 테스트가 증명한다)
- 관련: 원 설계 16절 "Electron Security"·17절, 이슈 #1 설계 분석 11번, [ARCHITECTURE 8절](../ARCHITECTURE.md)

## 맥락

제품은 개인 메일·메신저·업무 문서를 다루고, 신뢰할 수 없는 문서를 화면에 그리고 LLM에 넣는다. 이슈 #1은 "Local API token·Origin/Host·Electron sandbox/CSP/IPC 검증·암호화/키 정책·악성 문서 처리는 초기 slice부터 적용한다. Phase 7은 이를 처음 만드는 단계가 아니다"라고 정했다.

## 결정

V01의 첫 코드부터 아래를 전부 적용한다. 나중에 덧붙이지 않는다.

| 영역 | 기준 |
|---|---|
| Local API | 127.0.0.1에만 바인딩. 실행마다 새 세션 토큰. `Host`와 `Origin` 검사. 토큰이 없거나 틀린 요청은 거부 |
| Electron 화면 | contextIsolation 켬, sandbox 켬, nodeIntegration 끔 |
| preload·IPC | 필요한 함수만 노출. 모든 IPC 입력을 스키마로 검증. 화면에서 임의 셸·파일 접근 불가 |
| 화면이 불러오는 것 | CSP로 자기 출처만. 외부 URL 이동과 새 창 차단 |
| 가져온 내용 | 신뢰하지 않는 데이터로 표시하고 글자로만 그린다. LLM 입력에서는 지시와 구획을 나누고 응답을 스키마로 검증한다 |
| 로그 | 원문, 프롬프트, 응답 본문, 비밀 값, 토큰을 기록하지 않는다. 기록 전에 걸러 낸다 |
| 비밀 값 | OS 자격 증명 저장소에만 둔다. 실제 동작은 OS가 보호하는 키로 암호화한 암호문만 디스크에 두는 것이다([ADR 0010](0010-encryption-at-rest.md)) |
| 외부 전송 | 정책과 동의를 거친다([ADR 0014](0014-egress-policy-and-consent.md)) |
| CLI 실행 | 셸 없이 인자 배열, 빈 임시 디렉터리, 최소 환경 변수, 바깥에서 거는 시간 제한([ADR 0005](0005-llm-providers.md)) |

각 줄에는 **거부되는 경우를 확인하는 테스트**가 하나 이상 있어야 한다. 통과하는 경우만 있는 테스트는 통제가 사라져도 계속 초록이기 때문이다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 기능을 먼저 만들고 Phase 7에서 보안을 넣음 | 이슈 #1이 금지한다. 나중에 넣으면 API·IPC 계약이 바뀐다 |
| loopback이므로 토큰 생략 | 같은 PC의 다른 프로그램이나 브라우저에 열린 다른 사이트가 로컬 API를 부를 수 있다 |
| 가져온 HTML을 정리(sanitize)해서 그림 | Phase 1에는 필요한 화면이 없다. 글자로만 그리는 쪽이 공격면이 가장 작다. 서식 표시가 필요해지면 그때 결정한다 |

## 결과

- Playwright의 Electron 지원은 실험적이라고 문서화되어 있다([OSS_EVALUATION 4.2절](../OSS_EVALUATION.md)). Electron 쪽 보안 설정 테스트가 그 위에 선다.
- Windows에서 CLI의 OS 수준 격리는 약하다(CLI Provider 조사 Q2-C2). 이 기준선은 그것을 메우지 못하며 격리 검증은 R02의 몫이다.
- 정본 SQLite의 파일 단위 암호화는 이 기준선에 들어 있지 않다. 범위는 ADR 0010이 정한다.
