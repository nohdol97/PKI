# ADR 0014: 외부 전송 정책과 동의

- 날짜: 2026-11-21 / 상태: **확정**(정책의 모양. 등급과 규칙의 값은 배포처가 정한다)
- 관련: 원 설계 17절, 이슈 #1 설계 분석 5번, 이슈 #15 R06-C3, [ARCHITECTURE 5.1절·8절](../ARCHITECTURE.md), [ADR 0005](0005-llm-providers.md)

## 맥락

원 설계 17절: "Claude Code와 Codex가 로컬에서 실행되더라도 실제 추론 요청은 외부 서버로 전송될 수 있다", "승인되지 않은 업무 데이터는 외부 Provider로 전송하지 않는다". 이슈 #1은 원문뿐 아니라 요약·embedding 입력·그래프 경로·관련 문맥 같은 파생 데이터에도 원본의 접근 범위와 전송 정책이 따라가야 한다고 정했다.

## 결정

- 모든 원본은 접근 범위(access_scope)를 갖고, 여기서 **데이터 등급**이 정해진다. 여러 원본이 섞인 입력의 등급은 그중 가장 엄격한 값이다. 요약, 추출 결과, 관련 문맥도 자기가 나온 원본의 등급을 물려받는다.
- 전송 정책은 `(Provider, 작업 종류, 데이터 등급) → 허용 또는 거부` 규칙의 목록이다. **거부가 우선**하고, 맞는 규칙이 없으면 거부다.
- 공용 저장소의 기본 정책은 **외부 전송 전부 거부**다. 사용자가 Provider별로 동의해야 그 Provider에 대한 허용 규칙이 생긴다.
- 동의 화면은 어떤 데이터가 어디로 나가는지 보여 준다. CLI Provider도 "외부 전송"이라고 표시하고 "로컬 추론"이라고 부르지 않는다.
- 검사는 **호출 직전마다** Broker가 한다. 동의를 철회하거나 정책이 바뀌면 대기 중이던 작업도 다음 검사에서 막힌다.
- 거부되면 호출하지 않고 작업을 보류로 둔다. **다른 Provider로 몰래 넘어가지 않는다.**
- 호출 이력에는 Provider, 작업 종류, 등급, 정책 버전, 결과, 걸린 시간만 남기고 본문은 남기지 않는다.
- Embedding은 로컬 계산이라 이 정책의 대상이 아니다. 모델 파일을 내려받는 일은 네트워크 접근이므로 사용자 승인을 거친다([ADR 0006](0006-embedding.md)).

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 앱 전체에 대한 한 번의 동의 | Provider마다 데이터가 가는 곳이 다르다. 원 설계가 요구한 "전송 범위 제어"가 되지 않는다 |
| 원문에만 정책 적용 | 요약과 관련 문맥으로 같은 내용이 나간다 |
| 거부 시 허용된 다른 Provider로 자동 전환 | 사용자가 모르는 곳으로 데이터가 간다. 프로젝트 규칙이 조용한 대체를 금지한다 |

## 결과

- 등급의 종류와 각 등급에 허용할 Provider는 배포처가 정한다([site-setup.md](../site-setup.md) S08). 공용 저장소는 규칙의 형태와 기본 거부만 갖는다.
- 여러 원본을 종합하는 작업은 가장 엄격한 원본 하나 때문에 통째로 막힐 수 있다. 막힌 이유를 화면에 보인다.
- 질의응답과 알림 직전의 재검사는 그 기능이 생기는 Phase(X01, P02)에서 같은 Broker 검사를 쓴다.
