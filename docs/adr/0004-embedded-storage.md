# ADR 0004: 저장소 — better-sqlite3 정본, 벡터는 어댑터 뒤(sqlite-vec 후보), 그래프 DB 없음

- 날짜: 2026-11-21 / 상태: **잠정 — 배포처 검증 대기**
- 관련: 원 설계 15절, [ARCHITECTURE 4절·5.4절](../ARCHITECTURE.md), [OSS_EVALUATION 4.3절·4.7절·4.8절](../OSS_EVALUATION.md), 가정 A07, A08, A17

## 맥락

원 설계는 별도 DB 서버 없이 임베디드 저장소를 쓰라고 한다. 조사 결과(전부 설치·실행 없이 읽은 것이다):

- better-sqlite3: MIT, win32-x64 미리 빌드된 바이너리 동봉, 위험 "낮음". Electron에서 재빌드 없이 로드되는지는 추정이며 미시험(4.3절).
- sqlite-vec: MIT OR Apache-2.0, Windows용 바이너리 있음. 그러나 "pre-v1", 개인 유지보수자, 2026-05-21 이후 commit 0, 서명 없는 `vec0.dll`이 Windows Smart App Control에 차단된 이슈 #368이 있어 위험 "**높음**". 검색은 전수 비교다(4.3절).
- Kuzu는 보관 처리, LadybugDB는 그 포크로 0.x(4.3절, 4.7절 3번). cortexdb는 보류(5.1절).
- node:sqlite는 릴리스 후보 단계이고 확장 로딩이 Electron에서 되는지 미검증(4.3절).

## 결정

- **정본 데이터 전부**를 better-sqlite3로 SQLite 파일 하나에 둔다. 쓰는 쪽은 백엔드 프로세스 하나다.
- **벡터**는 `VectorIndex` 어댑터 뒤에 두는 투영이다. **Phase 1(V01)에는 규격, 계약 테스트, 테스트용 메모리 구현만 만들고 네이티브 벡터 모듈을 넣지 않는다.** 제품의 기본 구성은 "사용 불가"를 돌려주는 빈 구현에 묶인다.
- **sqlite-vec는 실제 구현의 잠정 후보**다. 배포처에서 로드와 서명 차단 여부를 확인한 뒤(A08) 채택 여부를 R07에서 정한다. 채택되면 별도 파일에 둔다.
- **Phase 1에 그래프 DB는 없다.** 관계는 정본의 행이다. LadybugDB나 cortexdb는 나중에 어댑터 뒤에서만 쓰며, 도입하더라도 투영이다.
- 정본 SQLite 앞에 좁은 **SQL 드라이버 포트**(열기, 실행, 트랜잭션)를 두어 드라이버를 바꿀 수 있게 한다. 확장을 불러오는 기능은 Phase 1에 쓰는 곳이 없으므로 포트에 넣지 않는다. 벡터 구현을 정할 때 필요하면 더한다.
- **키워드 검색**은 SQLite의 전문 검색 기능으로 정본 파일 안에 둔다. 모델이 없어도 동작해야 하기 때문이다. 쓰는 드라이버 빌드에 그 기능이 들어 있는지와 한국어 품질은 OSS_EVALUATION이 다루지 않았으므로 가정 A17로 둔다. 기능이 들어 있는지는 V01-T03의 테스트로 사외에서 확인할 수 있다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| sqlite-vec를 V01에 바로 넣음 | Phase 1 완료 기준 중 벡터 **검색**을 요구하는 것이 없다(V01-C6은 embedding 왕복만 요구). 위험 "높음"인 네이티브 모듈을 쓸 곳 없이 설치본에 넣게 된다 |
| LanceDB를 벡터 기본 후보로 | Apache-2.0이고 유지보수는 활발하나 win32-x64 바이너리가 압축 해제 약 356 MB다(4.3절). **차선**으로 남긴다 |
| node:sqlite | 릴리스 후보 단계, 확장 로딩 미검증(4.8절 "아직 채택하지 않음") |
| LadybugDB를 지금 도입 | Phase 1의 질의는 깊이 1 조인이라 그래프 DB가 필요 없다. 0.x이고 Windows 실행 미검증 |
| DuckDB | 관계형이고 2.0.x가 나온 지 하루였다(4.3절). SQLite 대비 이점이 Phase 1에 없다 |
| 벡터를 앱 코드의 전수 코사인 비교로 | OSS_EVALUATION 4.8절이 작은 코퍼스용 선택지로 든다. sqlite-vec가 배포처 확인을 통과하지 못할 때의 교체안으로 남긴다(A08) |

## 결과

- Phase 1의 설치본에 들어가는 네이티브 저장 모듈은 better-sqlite3 하나다.
- Phase 1에서 벡터 검색은 동작하지 않는다. 화면은 "벡터 검색 사용 불가"를 알리고 키워드 검색으로 동작한다. embedding 왕복(V01-C6)은 테스트용 메모리 구현으로 확인한다.
- 벡터에 실제 지식을 색인하는 첫 작업 전에 실제 구현을 골라야 한다. 그때까지 R07이 닫히지 않았으면 그 작업이 막힌다.
- 삭제한 원본의 내용이 SQLite 파일에 남지 않게 하려면 지운 자리를 실제로 덮어쓰는 설정이 필요하다. 그 동작은 V02의 테스트(삭제 뒤 파일에서 카나리가 사라졌는지)로 확인한다.
- 네이티브 모듈(`.node`, `.dll`)은 설치본에서 서명·압축 해제 설정이 따로 필요할 수 있다(4.7절 4번, A07).
- 정본 파일의 암호화는 [ADR 0010](0010-encryption-at-rest.md)에서 다룬다.
