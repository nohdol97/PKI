# 스펙: R01 오픈소스 엔진·스택 평가

- 날짜: 2026-11-21 / 상태: 확정
- 관련: 이슈 #10(R01), 이슈 #11(R02, 문맥), 총괄 #1, Phase 0 #2, 선행 #35. 원 설계: [docs/design/original-design.md](../design/original-design.md)

## 배경

제품 설계(원문은 위 링크)는 "Open Source First"를 원칙으로 하고, 지식 추출·저장·그래프·Wiki 엔진을 새로 만들지 않고 기존 오픈소스를 쓰도록 요구한다. 어떤 엔진과 스택을 쓸지는 아직 정해지지 않았다. 이 spec은 후보를 소스 수준에서 평가해 이후 단계(R03 실행 확인, R06 확정)가 쓸 근거 문서를 만드는 일의 기준을 고정한다.

제품 라이선스는 MIT로 2026-11-21에 정해졌다. 따라서 제품에 포함해 배포해야 하는 의존성이 GPL, AGPL, SSPL, BSL, 비상업 라이선스이면 탈락이다.

## 목표

- 계획된 후보 6개와 추가로 찾은 대안 후보를 고정된 commit 기준으로 같은 항목에서 비교한 표가 있다.
- 쉘·패키징·UI·저장소·문서 파싱·임베딩·Python 번들링 스택의 버전, 라이선스, Windows 바이너리, 유지보수 상태, 재배포 조건이 표로 있다.
- 점수를 매기기 전에 탈락 조건을 먼저 적용하고, 후보마다 채택/보류/기각과 기각 시 대안이 기록되어 있다.
- 모든 사실 칸은 URL 또는 permalink로 추적되고, 실행으로 확인하지 못한 것은 "미검증"으로 표시된다.

## 비목표

- 어떤 후보도 설치하거나 실행하지 않는다. 이 문서의 모든 "가능"은 "소스에 그 메커니즘이 있다"는 뜻이며, Windows 11에서의 실제 동작 확인은 R03, R04로 넘긴다.
- 엔진·저장 구조의 최종 결정은 하지 않는다(R06). 설계에 주는 영향은 잠정으로만 적는다.
- CLI 구독 로그인 허용 여부와 격리 검증은 R02에서 다룬다. 이 spec은 R02를 위한 문서 조사 결과만 별도 research 문서로 남긴다.
- 사내 수집기·사내 데이터·사내 환경 정보는 다루지 않는다(배포처 범위).

## 요구사항

- R01-R1: 후보별 표에는 고정 commit SHA, commit 날짜, 최신 release, 라이선스, 런타임, 탈락 조건 4종, 증분 갱신·삭제, 사용자 정의 LLM client, CLI adapter 지원, 사용자 정의 embedder, 시간 유효성 항목이 있고, 각 칸 또는 각 행에 소스 링크가 붙는다.
- R01-R2: 계획된 후보 외 대안은 후보 목록과 최종 후보군(shortlist), 기각 목록(기각의 결정적 이유 한 가지씩)으로 나눠 적는다. 성숙도 신호는 보고된 값 그대로 적고, 보고되지 않은 것은 미검증으로 표시한다.
- R01-R3: 스택은 그룹별(쉘·패키징, UI, 저장소, 문서 파싱, 임베딩, Python 번들링) 표로 버전, 라이선스, Windows 바이너리, 유지보수, 재배포 조건, 위험을 적는다.
- R01-R4: 판정은 탈락 조건을 먼저 적용한 뒤에만 내린다. 판정은 채택/보류/기각 중 하나이며 기각에는 대안을 적는다.
- R01-R5: 근거는 소스·메타데이터 읽기뿐임을 문서 앞부분에 밝히고, Windows 동작은 R03, R04 전까지 미검증으로 둔다.
- R01-R6: 판정에 영향을 주는 모든 미검증 항목은 R03에서 실행으로 확인할 체크리스트로 옮긴다.
- R01-R7: 사내 데이터, 로컬 경로, 이메일, 비밀 값을 문서에 넣지 않는다.

## 미해결 질문

- 사이드카(별도 프로세스) 언어를 Python, Go 단일 바이너리, 사이드카 없음 중 무엇으로 할지는 R03 이후 정한다.
- CLI 구독 로그인의 제품 자동화 허용 범위는 R02 조사 문서의 "결정이 필요한 위험"에 정리되어 있으며 사용자 결정이 필요하다.
