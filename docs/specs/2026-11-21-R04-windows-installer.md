# 스펙: R04 Windows 설치 파일 측정·점검 키트 (사외 준비물)

- 날짜: 2026-11-21 / 상태: 초안
- 관련: 이슈 #13(R04), 총괄 #1, Phase 0 #2, 선행 #10·#14·#12, 결과 수령 #37(R07). 근거: [원설계](../design/original-design.md) 16절, [OSS 평가](../OSS_EVALUATION.md) 4.1절·6절 3항. 같은 묶음: [R02 스펙](2026-11-21-R02-cli-isolation.md), [R03 스펙](2026-11-21-R03-engine-comparison.md)

## 배경

이슈 #13은 Browser UI + Local API + Electron 설치 경로를 깨끗한 Windows 11에서 검증하는 작업이다. 제품 코드가 아직 없으므로 **설치 파일 자체를 만들지 않는다.** V01(#16)이 만드는 skeleton 설치 파일이 생겼을 때 그것에 대해 돌릴 측정·점검 도구와 절차서만 준비한다. **이 키트는 V01 skeleton 산출물(설치 파일)이 있어야 의미가 있다. 그 전에는 실행할 대상이 없다.**

또 #13은 R05 기준 고정 전에는 비교·판정용 측정을 하지 말고 "무점수 skeleton 준비"만 하라고 한다. 이 키트는 숫자를 모으기만 하고 합격선을 정하지 않는다.

## 목표

- 설치 파일 하나를 받아 무인 설치·제거, 런타임 미설치 확인, 시작 시간, idle CPU·RSS, 단일 인스턴스·정상 종료, 제거 뒤 잔여 파일, 서명 상태를 같은 순서로 측정하는 스크립트가 있다.
- 사람이 봐야 하는 항목(SmartScreen 경고 화면, 서명·업데이트 배포 미확정 사항)은 체크리스트로 있다.
- 결과는 식별 정보가 없는 `result.json`/`result.md` 하나로 합쳐진다.

## 비목표 (배포처에서 후속 진행)

- Electron + Local API skeleton 설치 파일을 만드는 일. 제품 코드가 없다. (V01 이후, 배포처 Windows 11에서 후속 진행)
- 두 번째 설치 실험(R04-C2)에 쓸 Python/native 모듈 번들의 제작. R03에서 통과한 후보가 있어야 한다.
- 코드 서명 인증서 선정과 구입, 업데이트 서버 선정.
- PowerShell 스크립트를 사외에서 실행하는 일. 이 PR의 개발 기기에는 PowerShell이 없어 구문 검사도 하지 못했다.

배포처 후속 항목(각 항목은 `docs/site-setup.md`의 `## 배포처 설정 체크리스트`에 같은 ID로 있다):

- R04-S1: V01 skeleton 설치 파일 제작·전달. `run.py build-skeleton`은 안내만 출력한다.
- R04-S2: R04-C2 두 번째 설치 실험(Python/native 모듈 포함 번들). `run.py second-installer`는 안내만 출력한다.
- R04-S3: 코드 서명 인증서·업데이트 배포 경로 결정(체크리스트 기록). 스크립트 없음, 체크리스트로만 닫힌다.

## 요구사항

- R04-R1 (사전 점검): `01-preflight.ps1`은 Node/Python/Docker/DB 서버가 PATH와 설치 목록에 없음을 확인한다. 있으면 "깨끗한 환경 아님"으로 기록하고 이어서 진행하지 않는다.
- R04-R2 (설치·제거): `02-install-silent.ps1`과 `06-uninstall-leftovers.ps1`은 설정 파일이 정한 무인 인자로 설치·제거하고 종료 코드를 기록한다.
- R04-R3 (시작 시간): `03-startup-time.ps1`은 프로세스 시작부터 준비 신호(Local API 응답 또는 주 창 핸들)까지의 시간을 N회 잰다.
- R04-R4 (idle): `04-idle-sampling.ps1`은 준비 뒤 idle 상태에서 프로세스 트리의 RSS와 CPU를 일정 간격으로 표본 추출해 중앙값·p95·최대를 낸다.
- R04-R5 (수명주기): `05-single-instance-stop.ps1`은 두 번째 실행의 처리, 정상 종료 요청 뒤 종료 시간, 남은 자식(worker) 프로세스를 기록한다.
- R04-R6 (잔여): `06-uninstall-leftovers.ps1`은 설치 전 스냅샷과 제거 후 상태의 차이(파일, 레지스트리 Uninstall·Run 키, 시작 메뉴, 예약 작업, 서비스, 프로세스)를 기록한다. 전체 스냅샷은 결과에 넣지 않는다.
- R04-R7 (서명): `07-signature-info.ps1`은 설치 파일과 설치 폴더의 exe·dll·node 파일의 서명 상태를 센다.
- R04-R8 (round trip): `08-roundtrip.ps1`은 설정 파일이 정한 합성 요청으로 Local API 쓰기·읽기를 확인한다. 브라우저·Electron 화면 확인은 사람이 체크리스트로 한다.
- R04-R9 (결과·마스킹): PowerShell은 값을 만들 때부터 호스트명·사용자명·경로를 자리표시자로 바꾸고, `sanitize_result.py`가 다른 기기에서 한 번 더 마스킹·검증한다.
- R04-R10 (표기·문서): 스크립트 머리에 실행된 적 없음을 적는다. 한국어 절차서, 수동 체크리스트, 결과 양식, `docs/site-setup.md` 항목을 둔다.

## 인터페이스 / 설계 개요

경계는 설정 파일 하나(`config.json`: 설치 파일 경로, 무인 인자, 제품 exe 이름, 준비 신호, round trip 요청)다. 스크립트는 제품 구현을 모르고 설정만 읽는다. 결과는 R02·R03과 같은 `result.json` 모양이며 `sanitize_result.py`가 `common`의 마스킹과 스키마 검증을 재사용한다.

## 완료 기준 (테스트 가능한 형태)

### 이슈 #13의 기준 (원문 그대로)

- [ ] R04-C1: Windows 11 깨끗한 환경에서 Node/Python/Docker/DB 서버 별도 설치 없이 설치·실행·제거한다. 합성 backend round trip이 browser와 Electron 모두 동작한다.
- [ ] R04-C2: R03(#12)에서 실행을 통과한 후보 중 가장 유력한 하나 이상의 Python/native 모듈을 포함한 두 번째 설치 실험으로 실행 파일·의존 라이브러리·worker lifecycle을 검증한다.
- [ ] R04-C3: 크기/idle CPU·RSS/시작 시간과 서명·업데이트 배포에 필요한 미확정 사항을 기록한다. Windows 실행 환경 없이는 통과 처리하지 않는다. 검증 환경은 배포처의 Windows 11이다.

## 미해결 질문

- NSIS 무인 설치 인자와 제거 파일 이름은 electron-builder 문서로 설치 파일을 받은 뒤 `config.json`에 적는다. 잠정 예시(`/S`)는 설정 예시 파일에만 있고 근거 확인 전이다.
- idle 상태의 정의(준비 신호 뒤 몇 초, 몇 분 관찰)는 R05가 정한다. 잠정으로 워밍업 30초, 관찰 300초, 간격 5초를 설정 기본값으로 둔다. 바꾸는 법: `config.json`의 `Idle`.
