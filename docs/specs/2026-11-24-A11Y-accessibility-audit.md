# 스펙: 접근성 자동 점검(A11Y) — 모든 메뉴 화면의 axe 검사와 키보드만으로 가는 흐름 하나

- 날짜: 2026-11-24 / 상태: 초안(잠정 결정 D1~D8 포함)
- 관련: 이슈 #34(H03), #308(UI01 후속의 접근성 줄). [X02 spec](2026-11-23-X02-explore-ux.md)("넘기는 것"의 H03 줄, "검증하지 않는 범위"), [UI01 spec](2026-11-24-UI01-ab-light-panes.md)
- 번호: 요구사항 `A11Y-R<n>`, 완료 기준 `A11Y-C<n>`, 결정 `A11Y-D<n>`, 작업 `A11Y-T<n>`. 고치는 곳은 `apps/web`과 루트 `package.json`(개발 의존 하나)뿐이다. 계약·백엔드·마이그레이션은 없다.

## 배경

X02는 "접근성 실사용 점검"을 H03(#34)으로 넘겼고, 그 뒤 화면 시험은 역할·이름·초점만 봤다. 단계 관문 검토에서 이 항목만 증거가 없었다. 저장소에는 접근성 규칙을 기계로 돌리는 검사(axe 같은 것)가 하나도 없다. 그래서 글자 명암비, 이름 없는 버튼·입력 칸, 잘못된 ARIA 값 같은 것은 누가 눈으로 보기 전에는 드러나지 않는다.

이 묶음은 그 빈자리를 **기계가 볼 수 있는 만큼** 채운다. 자동 도구는 접근성 문제의 일부만 잡는다(화면 낭독기가 실제로 어떻게 읽는지는 못 본다). 못 보는 것은 "미검증 범위"에 그대로 남긴다.

## 목표

1. 메뉴에서 갈 수 있는 모든 화면이 자료가 있는 상태에서 WCAG 2.1 A·AA 자동 검사를 통과한다(심각한 위반 0건).
2. 마우스 없이 키보드만으로 주 흐름 하나(메뉴 → 화면 → 항목 → 근거)를 끝까지 갈 수 있다.
3. 검사가 못 고친 것과 못 본 것이 표로 남는다.

## 비목표

- 화면 낭독기로 실제 들어 보기, Windows 배율·고대비, Electron·설치본에서의 검사. "미검증 — 배포처/Windows"로 남는다.
- 새 기능(#290), 화면 다시 그리기, `moderate`·`minor` 위반 고치기(표에 적기만 한다).
- **`evidence-view.tsx`, `notifications.tsx`, `wiki.tsx`, `lint.tsx`와 그 시험은 고치지 않는다**(UI01G 묶음이 지금 고치는 중이다). 이 네 파일 안에서만 고칠 수 있는 위반은 "UI01G 머지 뒤"로 미룬다(R4).
- 화면마다의 키보드 흐름, 경계값·조합의 전수 시험, 최종 시나리오 표(`eval/final-scenarios.json`) 변경 — FS01~FS14에 접근성 행이 없다.

## 요구사항

- **A11Y-R1** 브라우저 E2E 하나가 메뉴의 열한 화면(홈, 원본, 알림, 위키, 점검, 질문, 탐색, 지식 검토, 유형 정의, 활동, 설정)을 각각 자료가 보이는 상태에서 `@axe-core/playwright`로 검사한다. 규칙은 `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` 태그다.
- **A11Y-R2** 같은 검사를 상세 칸이 열린 상태 하나에서도 한다: 탐색에서 항목을 고르고 사실의 근거 원본까지 연 화면.
- **A11Y-R3** 통과선은 화면마다 영향도 `serious`·`critical` 위반 0건이다. 걸린 위반은 제품 코드에서 고친다(네 파일 밖).
- **A11Y-R4** 네 파일 안에서만 고칠 수 있는 위반은 시험 파일의 예외 목록에 한 줄씩 적는다: 화면, 규칙 id, CSS 선택자, 이유. 규칙 전체를 끄거나 화면 전체를 빼지 않는다. 예외는 그 네 파일이 그리는 화면(홈, 알림, 위키, 점검)에만 둘 수 있고, 더는 맞는 위반이 없는 예외는 시험을 실패시킨다(고쳐진 뒤에 남은 예외를 지우게 한다).
- **A11Y-R5** 키보드만 쓰는 E2E 하나: Tab으로 메뉴에 닿아 "탐색"을 열고, 이름으로 찾아 항목 줄을 고르고, 사실의 "근거 보기"를 열면 초점이 근거 원본의 제목에 놓인다. 시험은 마우스 누름과 `focus()` 호출을 쓰지 않는다.
- **A11Y-R6** 검사가 보고한 `moderate`·`minor` 위반과 미룬 예외를 아래 "남김 표"에 적는다.

## 인터페이스 / 설계 개요

새 파일은 `apps/web/e2e/a11y.e2e.ts` 하나다. 브라우저 묶음의 `testMatch`에 저절로 들어가고 Electron 묶음에는 넣지 않는다(`playwright.config.ts`는 그대로다). 띄우는 방법은 기존 화면 시험과 같다: seed 스크립트로 데이터 폴더를 채운 뒤 `webConfig`로 Vite 개발 서버를 연다(`apps/web/e2e/lint.e2e.ts`와 같은 모양). 한 seed로 모든 화면이 차지 않으므로 둘을 쓴다(D4). 그림은 넣지 않는다(파일 하나, 갈래 없는 순서).

## 완료 기준 (테스트 가능한 형태)

| 기준 | 문장 | 증명 테스트 |
|---|---|---|
| A11Y-C1 | seed로 띄운 화면에서 메뉴의 열한 화면을 차례로 열어, 그 화면의 자료가 보인 뒤 검사하면 예외 목록에 없는 `serious`·`critical` 위반이 0건이다. 각 검사는 통과한 규칙이 1개 이상이다(빈 화면을 검사하고 통과하는 일을 막는다). 메뉴 버튼 수가 시험의 화면 목록 길이와 같다(R1, R3) | `apps/web/e2e/a11y.e2e.ts` |
| A11Y-C2 | 탐색에서 항목을 고르고 근거 원본이 보일 때 검사하면 `serious`·`critical` 위반이 0건이다(R2, R3) | 같은 파일 |
| A11Y-C3 | 예외 목록의 각 줄은 화면·규칙 id·선택자·이유를 가지며 화면이 홈·알림·위키·점검 가운데 하나다. 검사 결과에 맞는 위반이 없는 예외가 있으면 시험이 실패한다(R4) | 같은 파일 |
| A11Y-C4 | 페이지를 연 뒤 키보드 입력만으로 "탐색"을 열고, 항목을 찾아 고르면 그 항목 제목에, 사실의 "근거 보기"를 Enter로 열면 "근거 원본" 영역의 제목에 초점이 있다(R5) | 같은 파일 |

기준마다 대표 사례 하나다. 변이 검사는 하지 않는다(허용·차단을 정하는 보안 검사가 아니다). 대신 C1의 "통과한 규칙 1개 이상"과 "자료가 보인 뒤"가 헛통과를 막는다.

## 잠정 결정

| 결정 | 내용 | 이유 | 바꾸려면 |
|---|---|---|---|
| A11Y-D1 | 도구는 `@axe-core/playwright`(개발 의존) | 표준 도구이고 이 기기 안에서만 돌며 밖으로 보내는 자료가 없다. 설치본에 들어가지 않는다 | 루트 `package.json`과 시험의 import |
| A11Y-D2 | 규칙은 WCAG 2.1 A·AA 태그 넷, 통과선은 `serious`·`critical` 0건 | 기준이 분명하고, 가벼운 지적까지 막으면 이 묶음이 화면 다시 그리기가 된다 | 시험의 태그 목록과 영향도 거르기 |
| A11Y-D3 | 브라우저 묶음만. Electron·Windows는 배포처 항목 | 쉘은 같은 화면을 싣고 더하는 단언이 없다(간략화 규칙 3) | `playwright.config.ts`의 electron `testMatch` |
| A11Y-D4 | seed 둘: `k02-seed`(알림을 뺀 열 화면과 C2·C4), `p02-seed`(알림). 새 seed를 만들지 않는다 | 알림 줄은 `p02-seed`만 만들고, 점검 발견은 `k02-seed`만 만든다 | 시험의 seed 표 |
| A11Y-D5 | "질문"은 묻기 전 상태만 검사한다. 답이 그려진 상태는 남김 표로 | 답을 받으려면 Provider 대역을 묶은 세 번째 구성이 필요하다 | `ask.e2e.ts`의 구성을 시험에 더한다 |
| A11Y-D6 | 키보드 흐름은 탐색에서 한다 | 초점 이동이 이미 있고(`explore.tsx`), 고칠 일이 생겨도 네 파일 밖이다 | C4의 화면을 바꾼다 |
| A11Y-D7 | 예외는 결과를 거르는 목록으로 둔다(규칙 끄기·영역 빼기 아님) | 같은 규칙의 다른 위반과 같은 화면의 다른 요소는 계속 잡힌다 | 예외 줄을 지운다 |
| A11Y-D8 | #308의 접근성 세 줄(제목 단계 건너뜀, 알림 배지 이름, 관계 그림 선 명암비)은 이 검사가 잡지 않으면 고치지 않는다 | 제목 단계는 권장 규칙(태그 밖)이고, 선 명암비(비텍스트)는 axe가 재지 않는다. 제목 단계는 네 파일 안이다 | 요구사항을 하나씩 더한다 |

## 미검증 범위

- 화면 낭독기의 실제 낭독, Windows 11 글꼴·배율 125·150%·고대비, Electron·설치본 — 미검증(배포처/Windows).
- axe가 "판정 못 함"(`incomplete`)으로 돌려준 것(배경이 겹친 글자의 명암비 등)은 세지 않는다.
- 개발 서버의 화면을 검사한다. 빌드한 화면은 같은 CSS·마크업이지만 따로 검사하지 않는다.
- 네 파일에 건 예외의 위반은 UI01G 머지 뒤 고칠 때까지 남는다.
- 키보드 흐름은 탐색 하나다. 다른 화면의 Tab 순서는 보지 않는다.
