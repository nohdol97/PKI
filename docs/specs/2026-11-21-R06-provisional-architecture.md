# 스펙: R06 조사 근거로 아키텍처·보안·소유권 ADR 잠정 확정

- 날짜: 2026-11-21 / 상태: 초안
- 관련: 이슈 #15(R06), 총괄 #1, Phase 0 #2, 선행 #10(R01)·#14(R05), 확정 #37(R07). [문서 색인](../README.md)

낯선 말은 [ARCHITECTURE 0절](../ARCHITECTURE.md#0-처음-나오는-말)에 풀이가 있다.

## 배경

원 설계의 구조는 후보다. Phase 1 개발을 시작하려면 저장소, 엔진, 런타임, 그리고 무엇이 바뀔 수 있는지의 경계를 정해야 한다. 그런데 엔진, CLI, Windows 설치 파일의 실행 검증은 배포처에서만 할 수 있다. 그래서 이 작업은 소스 조사 근거(R01)만으로 결정을 **잠정**으로 내리고, 실행 근거가 필요한 결정에는 "잠정 — 배포처 검증 대기"를 붙이고 가정 목록을 남긴다. 확정은 R07(#37)에서 한다.

**이 작업이 놓인 자리(2026-11-21 기준).** 이슈 #15가 선행으로 든 #10(R01)과 #14(R05)는 둘 다 **아직 열려 있다.** 이 문서 묶음이 올라선 branch의 바탕은 `main`이 아니라 R01의 **병합되지 않은 PR #36**이다. R05는 PR #38로 열려 있다. 따라서 이 묶음의 PR은 이슈 #15를 닫지 않고 `Refs #15`로만 잇는다. 사용자 확인이 필요한 결정도 남아 있다(아래 표).

## 목표

- 개발자가 Phase 1(V01, V02)을 시작하는 데 필요한 구조, 결정, 구현 기준이 저장소에 문서로 있다.
- 실행해 보지 않은 것은 어디에도 통과나 확정으로 적혀 있지 않다.
- 뒤집힐 수 있는 선택이 무엇이고, 뒤집히면 무엇을 바꾸는지 한 표에서 볼 수 있다.
- 사용자가 정해야 하는데 아직 정하지 않은 것이 정해진 것처럼 적혀 있지 않다.

## 비목표 (배포처에서 후속 진행)

**공용 저장소의 뒤 작업으로 넘기는 것**

- 제품 코드. 이 작업은 문서만 만든다.
- R02·R03·R04의 실행 절차서와 결과 기록 양식. 각 작업의 사외 준비물이다.
- Phase 2 이후의 구현 spec. 각 작업을 시작할 때 쓴다([문서 색인의 작성 계획](../README.md#앞으로-쓸-spec)).

**배포처 후속 항목**

이 작업이 따로 만드는 배포처 후속 항목은 없다. 배포처가 할 일은 Phase 1 spec 두 건의 비목표에 적혀 있고([V01](2026-11-21-V01-vertical-skeleton.md) S01~S13, [V02](2026-11-21-V02-vertical-slice.md) S14~S15), 그 15개가 [site-setup.md](../site-setup.md#배포처-설정-체크리스트)의 체크리스트다. 이 작업에는 실행할 코드 경로가 없으므로 "미구현 경로" 기준도 그 두 spec(V01-H1·H2, V02-H1·H2)이 진다.

## 요구사항

- **R06-R1 산출 문서.** ARCHITECTURE, ADR 묶음과 색인, ownership, site-setup, 재사용·직접 개발 목록, V01·V02 구현 spec, 문서 색인을 `docs/`에 둔다. site-setup.md는 `## 배포처 설정 체크리스트`라는 제목 아래에 번호가 붙은 항목을 갖는다.
- **R06-R2 최초 base 보관.** 이슈 #35의 절차와 실행 증거를 저장소 안 문서로 옮긴다.
- **R06-R3 정본과 투영.** 데이터 종류마다 저장 위치, 정본인지 투영인지, 잃었을 때의 복구를 표로 적는다. 벡터, 그래프, Wiki 각각에 대해 투영인지를 밝힌다.
- **R06-R4 부분 실패 복구.** 저장소 사이에서 중간에 꺼졌을 때의 복구 방식을 정한다.
- **R06-R5 보안·데이터 결정.** OS 계정 격리, 암호화 대상과 키 보관, 백업 암호화, 임시 파일과 로그, LLM 전송 승인, embedding 실행 경로와 모델 파일의 포함·내려받기·갱신, 포크가 지킬 규격을 각각 결정으로 적는다.
- **R06-R6 가정 표.** 실행 증거가 없는 항목마다 가정, 걸려 있는 결정, 확인하는 방법(누가 언제 하는지 포함), 틀렸을 때 바뀌는 것을 적는다.
- **R06-R7 어댑터 경계.** 엔진, Provider, 저장소, embedding을 어댑터 뒤에 두라는 요구를 Phase 1 spec의 요구사항과 완료 기준에 넣는다. 규격마다 그것을 **부르는 자리**와 구현을 바꿔 끼웠을 때 달라지는 것을 확인하는 테스트가 있어야 하고, 부르는 자리가 없는 경로는 미증명이라고 적는다.
- **R06-R8 엔진 재개발 금지.** 실행을 통과한 엔진이 없을 때의 길이 "대안 조사"이고 자체 엔진 개발이 아님을 결정 기록에 적는다. 제품이 직접 하는 일과 엔진의 일을 가르는 선을 테스트할 수 있는 규칙으로 적는다.
- **R06-R9 출처 일치.** 오픈소스 구성요소에 관한 서술은 OSS_EVALUATION의 해당 절과 맞아야 하고, Windows에서 동작한다거나 벤더가 허용한다는 서술을 하지 않는다. 문서 근거가 없는 사실은 누구의 진술인지와 함께 적는다.
- **R06-R10 사용자 결정의 표시.** 사용자가 정할 일을 잠정으로 고른 경우 그 사실, 어긋날 수 있는 원 설계 문장이나 사용자가 알아야 할 결과, 번복되면 다시 하는 작업을 한곳에 모아 적는다.

## 인터페이스 / 설계 개요

문서 작업이며 코드 경계는 바뀌지 않는다. 산출 문서와 그 관계는 [문서 색인](../README.md)에 있다. 구조 그림은 [ARCHITECTURE 2절·6절](../ARCHITECTURE.md)에 있으므로 여기에 다시 그리지 않는다.
