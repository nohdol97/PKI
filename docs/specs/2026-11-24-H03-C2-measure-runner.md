# H03-C2 — 측정 실행기 (공용 저장소에서 돌릴 수 있는 범위)

- 상태: 초안
- 이슈: #34 (H03-C2 가운데 Windows 설치본 없이 도는 부분만. 총괄 #1, Phase #9)
- 날짜: 2026-11-24
- 관련: [EVALUATION 2.4절·4.4절·5절](../EVALUATION.md)(지표 정의, 통과선, 함께 적을 환경), [H03-C1 spec](2026-11-24-H03-C1-security-negative-tests.md)

## 배경

H03-C2는 "R05 고정 환경에서 installer 크기·idle CPU/RSS·처리 및 검색 p95·LLM 호출·저장 증가율·장시간 안정성·강제종료·복구를 측정한다"이다. R05가 고정한 것은 [EVALUATION 4.4절](../EVALUATION.md)의 통과선과 판정 환경(등급 A: Windows 11, 논리 코어 8개 이상, RAM 16 GB, 코퍼스 T2)이다. 그 환경과 설치 파일은 배포처에만 있다(#33, #37).

공용 저장소에서 먼저 할 수 있는 일은 **같은 지표를 같은 정의로 재는 실행기**를 만드는 것이다. 실행기는 합성 문서를 만들어 실제 백엔드(실제 서버·정본 SQLite·작업 실행기·Broker)에 넣고 숫자를 결과 파일 하나로 남긴다. 배포처는 나중에 같은 명령을 등급 A 장비에서 돌려 판정한다. 개발 장비에서 나온 숫자는 판정이 아니라 참고값이다.

## 목표

- 명령 하나로 EVALUATION 2.4절 지표 가운데 설치본 없이 잴 수 있는 것(유휴 CPU·RSS, 문서 처리 시간, 검색 응답 시간, LLM 호출 수, 저장 증가율, 강제 종료 뒤 복구, 길이를 정할 수 있는 연속 가동)을 재고, 버전이 붙은 JSON 결과 파일 하나를 남긴다.
- 결과 파일만 읽어도 어디서·무엇으로 쟀는지와 **재지 못한 것**이 무엇인지 알 수 있다.

## 비목표

- 설치 파일 크기, Windows·설치본에서의 측정, 실제 Provider, 수 시간짜리 연속 가동의 실제 실행. 결과 파일의 `unverified`에 적기만 한다.
- 통과·실패 판정. 등급 A 환경과 코퍼스 T2가 아니므로 통과선은 값 옆에 적기만 한다(R8).
- 제품 코드 변경. 측정이 통과선을 넘는 값을 보여도 이 작업에서 고치지 않고 후속 이슈로 남긴다.
- 지식·검색 품질 지표(EVALUATION 2.1~2.3절), 백그라운드 작업 24시간 성공률, 벡터 색인을 켠 상태의 측정, 로컬 파일 수집 경로(I02B-C27이 따로 잰다).
- H03-C3, `docs/site-setup.md`에 배포처 항목을 더하는 일(후속 이슈).
- 다른 세션이 작업 중인 파일(Phase 3 후속, H02의 셸·업데이트·SBOM) 수정.

## 요구사항

- **H03C2-R1 (실행)** 명령 하나가 임시 데이터 폴더에 실제 백엔드를 **별도 프로세스**로 띄우고(측정하는 쪽의 CPU·메모리가 섞이지 않게), 정해진 씨앗으로 만든 합성 문서를 제품의 가져오기 API로 넣고, 아래 지표를 재고, 끝나면 자식 프로세스와 임시 폴더를 남기지 않는다. 네트워크를 쓰지 않는다. Provider는 대역(stub) 하나뿐이다.
- **H03C2-R2 (결과 파일)** 결과는 `eval/results/<이름>.json` 하나다. `schemaVersion`(1), 실행 시각, 제품 commit과 작업 트리가 깨끗한지, 실행 방식(`source-run` 또는 `test-build`), 환경(CPU 모델, 논리 코어 수, RAM, OS, Node 버전, 등급 A·B 해당 여부), 실행 인자(문서 수, 문서 크기, 질의 수, 워밍업 수, 유휴·연속 가동 초, 대역 지연, 작업 임대 시간), Provider(`kind: "stub"`와 그 뜻), 지표별 값, `unverified` 목록을 담는다.
- **H03C2-R3 (유휴)** 넣은 작업이 모두 끝난 뒤 정해진 시간 동안 백엔드 프로세스의 CPU 사용률 평균(전체 논리 코어 대비 %)과 RSS(최소·중앙·최대)를 밖에서 표본 추출한다. 관찰 시간이 EVALUATION의 10분보다 짧으면 그 사실을 값 옆에 적는다.
- **H03C2-R4 (처리·검색 시간)** 문서를 한 건씩 넣으며 ① 넣은 뒤 검색에 잡힐 때까지 ② 지식 추출 작업이 끝날 때까지를 재어 p50·p95를 낸다. 검색은 질의마다 그 질의가 찾아야 할 문서가 결과에 있는지 확인한 뒤의 시간만 세고, 앞의 워밍업 질의는 버린다. p50·p95를 함께 적는다.
- **H03C2-R5 (LLM 호출)** 제품이 남긴 Provider 호출 이력에서 호출 수를 작업 종류별로 세고(재시도 포함) 문서 한 건당 평균을 낸다. 값에는 대역이 답한 호출이라는 표시가 붙는다.
- **H03C2-R6 (저장 증가)** 문서를 N건 넣을 때마다 데이터 폴더 크기와 그때까지 넣은 원문 글자의 바이트 수를 적고, 마지막 지점의 `(데이터 폴더 크기 − 원문 크기) / 원문 크기`를 낸다.
- **H03C2-R7 (강제 종료·복구)** 추출 작업이 도는 중에 백엔드를 강제 종료(`SIGKILL`)하고 같은 데이터 폴더로 다시 띄운 뒤 같은 문서를 다시 보낸다. 다시 뜬 뒤 첫 작업이 실행되기까지의 시간, 모든 작업이 끝나기까지의 시간, 유실된 문서 수, 중복 생성된 지식 항목 수를 적는다.
- **H03C2-R8 (통과선)** 지표마다 EVALUATION 4.4절의 통과선을 글자 그대로 옆에 적는다. 결과 파일은 통과·실패를 말하지 않고, 판정이 아닌 이유(등급·코퍼스·대역)를 한 번 적는다. 통과선 숫자는 EVALUATION에서만 가져오고 새로 만들지 않는다.
- **H03C2-R9 (재지 못한 것)** 재지 못한 칸은 비우지 않고 `not-measured`와 이유를 적는다. `unverified`에는 항상 네 가지(설치 파일 크기, Windows·설치본, 실제 Provider, 수 시간 연속 가동)가 있고, 그 실행에서 재지 못한 지표가 더해진다.
- **H03C2-R10 (연속 가동)** 길이(초)를 인자로 받는다. 기본은 0(하지 않음)이다. 0보다 크면 그 시간 동안 넣기·검색을 되풀이하고 충돌 횟수와 처음·끝의 RSS를 적는다.
- **H03C2-R11 (시험 부담)** `pnpm test`에는 작은 값으로 한 번 도는 시험만 들어간다. 실제 측정(기본 인자, 강제 종료 포함)은 명령을 직접 돌릴 때만 일어난다.

## 완료 기준

- **H03C2-C1** (R1·R2·R8·R9) 작은 값(문서 몇 건, 질의 몇 개, 유휴 1초, 연속 가동 0, 강제 종료 생략)으로 실행기를 돌리면: 결과가 `schemaVersion` 1이고, 제품 commit·환경·실행 인자가 있고, Provider가 `stub`으로 적혀 있고, 유휴·처리·검색·LLM 호출·저장 지표가 유한한 양수이고, 통과선 글자가 EVALUATION 4.4절의 해당 줄과 같고, 통과·실패 필드가 없고, `unverified`에 고정 네 가지와 생략한 두 지표(강제 종료, 연속 가동)가 이유와 함께 있다. 끝난 뒤 자식 프로세스와 임시 폴더가 없다.
- **H03C2-C2** (R4·R5·R6) 같은 작은 실행에서: LLM 호출 수가 제품의 호출 이력 건수와 같고, 저장 지점의 원문 바이트가 만들어 넣은 문서의 바이트 합과 같고 지점마다 줄지 않는다. 질의가 찾아야 할 문서가 결과에 없도록 꾸미면(없는 낱말로 질의) 실행기는 시간을 세지 않고 오류로 끝난다.
- **H03C2-C3** (R7) 임대 시간을 짧게 한 시험 빌드의 백엔드로 강제 종료를 재면: 죽인 시점에 실행 중이던 작업이 있었고, 다시 뜬 뒤 모든 작업이 끝나고, 유실 문서 0건, 중복 지식 항목 0건, 재개 시간이 유한한 양수이고, 결과의 실행 방식이 `test-build`로 적힌다. 남은 자식 프로세스가 없다. (POSIX 한정, Windows에서는 건너뛴다.)
- **H03C2-C4** (R2·R3·R7·R11) 개발 장비에서 기본 인자로 한 번 돌린 결과 `eval/results/h03-c2-dev.json`이 저장소에 있고, 같은 검사기를 통과하며, 실행 방식이 `source-run`이고 강제 종료 지표가 측정된 값이다. PR 본문에 명령·관찰한 출력·미검증 범위를 적는다.
- **H03C2-C5** (R11) PR 직전 전체 실행(`pnpm lint`, `pnpm typecheck`, `pnpm test`)이 통과하고, README에 측정 명령 한 줄이 있다.

허용·차단을 가르는 가드를 만들지 않으므로 변이 확인은 하지 않는다.

## 잠정 결정

| 결정 | 이유 | 바꾸려면 |
|---|---|---|
| **D1** 실행기는 `backend/src/system-measure*.test-support.ts`에 둔다(`tooling/poc`가 아니다) | `tooling/poc`는 타입 검사에서 빠져 있고 모듈 경계 규칙을 주석으로 끄는 일회용 자리다. `backend/src`의 `.test-support.ts`는 타입 검사를 받고, Provider 대역(`@pki/testkit`)을 규칙 안에서 쓸 수 있고, 제품 빌드에 들어가지 않는다. X01의 측정 명령이 같은 자리에 있다 | 파일을 옮기고 README의 명령 경로를 고친다 |
| **D2** 통과선은 적되 판정하지 않는다 | 4.4절의 통과선은 등급 A(Windows 11)와 코퍼스 T2에서만 판정한다. 개발 장비·작은 코퍼스·대역의 값에 통과를 붙이면 확인하지 않은 것을 확인한 것처럼 읽힌다 | 배포처가 등급 A에서 돌린 결과에 판정 칸을 더하는 요구사항 추가 |
| **D3** 기본 인자는 짧다: 문서 200건(건당 약 10 KB), 질의 220개(앞 20개 워밍업), 유휴 30초, 연속 가동 0초 | 한 번 도는 데 몇 분 안에 끝나야 PR마다 다시 잴 수 있다. 문서 크기와 워밍업 수는 EVALUATION의 값이다 | 인자(`--sources`, `--queries`, `--idle-seconds`, `--soak-seconds`)로 T2(10,000건)·10분·수 시간을 준다 |
| **D4** 강제 종료 측정은 제품의 작업 임대 시간(2분)을 그대로 둔다. 시험만 시험 빌드로 임대를 줄인다 | 임대 시간을 줄인 값은 제품의 복구 시간이 아니다. 죽을 때 돌던 작업은 임대가 끝나야 다시 잡히므로 기본 실행은 2분쯤 더 걸린다 | `--skip-kill`로 생략한다. 임대 시간 자체를 바꾸는 것은 제품 변경이라 별도 작업 |
| **D5** "작업 재개"는 다시 뜬 뒤 **아무 작업이든 처음 실행되기까지**로 재고, 죽을 때 돌던 작업이 끝나기까지는 "모두 끝나기까지"로 따로 적는다 | EVALUATION의 "재시작 후 60초 안에 작업 재개"가 어느 쪽인지 문서가 정하지 않았다. 둘 다 적으면 어느 해석으로도 읽을 수 있다 | EVALUATION이 뜻을 정하면 한쪽만 남긴다 |
| **D6** 대역은 문서마다 고정 문장을 인용한 지식 한 줄을 돌려준다(여러 문서가 같은 이름의 항목을 가리킨다) | 빈 답이면 "중복 지식 항목 0건"이 언제나 참이라 아무것도 재지 못한다 | 대역의 답을 바꾼다. 실제 추출의 호출 수·시간은 배포처에서 실제 Provider로 잰다 |
| **D7** 저장 증가율은 "데이터 폴더 전체 − 원문"으로 어림한다 | 원문과 파생물(키워드 색인·지식·Wiki)이 같은 정본 SQLite 파일에 있어 파일 크기로는 가를 수 없다. 벡터 색인은 기본 꺼짐이라 들어가지 않는다 | 테이블별 크기(`dbstat`)로 파생물만 세는 요구사항 추가 |
| **D8** 이번 판에서 재지 않는 것: 문서 한 건당 **최대** 호출 수, Q&A 한 건당 호출 수, 하루 총 호출 | 호출 이력에는 문서 번호가 없어 건별 최대를 낼 수 없고, Q&A는 답변 대역이 따로 필요하다. 결과에는 `not-measured`와 이유로 적힌다 | 후속 이슈로 답변 대역(`x01-ask-double.e2e.ts`)을 묶어 더한다 |
| **D9** 유휴 표본은 POSIX의 `ps`로 읽는다. Windows에서는 유휴와 강제 종료 지표가 `not-measured`다 | 공용 저장소는 Windows에서 돌려 보지 못했다. R04 키트의 PowerShell 표본 추출이 설치본 쪽을 맡는다 | Windows 표본 추출을 더하고 Windows에서 실행해 확인 |

## 미검증 범위

- **설치 파일 크기, Windows 11 설치본**: 재지 않았다. R04 키트(`verification/r04-windows-installer/`)와 H03-C3, #33·#37의 몫이다.
- **등급 A·코퍼스 T2에서의 값**: 개발 장비(macOS)의 숫자는 통과선과 견줄 수 없다.
- **실제 Provider**: 호출 수와 추출 시간은 대역의 값이다. 실제 모델의 재시도·시간은 모른다.
- **수 시간 연속 가동**: 인자는 있지만 72시간은 물론 1시간도 돌리지 않았다.
- **Windows에서의 강제 종료**: `SIGKILL`에 해당하는 종료 뒤의 SQLite 상태(ARCHITECTURE 가정 A26)는 확인하지 않는다.
- **임베딩 모델을 올린 상태의 유휴 메모리**: EVALUATION은 모델을 메모리에 올린 상태를 기준으로 하지만 이 실행은 모델을 올리지 않는다.
