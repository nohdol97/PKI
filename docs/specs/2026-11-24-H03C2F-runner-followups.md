## 목표

1. 강제 종료 지표(유실·중복·재개 시간)가 실제로 일어난 일을 센다.
2. 결과 파일이 "어떤 조건에서 쟀는가"를 빠뜨리지 않는다(유휴 때 남은 작업, macOS의 RSS, 재지 못한 하위 지표).
3. 실행기가 중간에 끊겨도 프로세스와 임시 폴더를 남기지 않고, 있는 결과 파일을 말없이 덮어쓰지 않는다.

## 비목표

- **긴 측정을 다시 돌리지 않는다.** 추적 중인 `eval/results/h03-c2-dev.json`은 그대로 두고 그대로 유효하다(D1).
- **유휴 전에 대기 작업을 비우지 않는다.** 호출 예산 설정(`providers.callBudget.maxCalls`)을 실행기가 올려 200건을 모두 추출하는 일은 측정 조건을 바꾸므로 후속이다(D3).
- macOS의 다른 메모리 측정 방법(`footprint`, `vmmap`), Windows 표본 추출, `docs/site-setup.md` 항목, 등급 A·T2·장시간 실행.
- 제품 코드, `packages/contracts`, 원 spec의 D8 하위 지표를 실제로 재는 일.

## 요구사항

- **H03C2F-R1 유실·중복을 근거 줄로 센다.** 복구 단계는 다시 뜬 뒤 대역이 만든 항목의 사실과 근거 줄 수를 읽어 `knowledge: { facts, evidence, expectedEvidence }`로 적는다(`expectedEvidence`는 문서 수). 유실 문서 수는 "검색에 안 잡힌 문서 수 + 모자란 근거 줄 수", 중복 수는 "같은 이름 항목 수 − 1 + 남는 근거 줄 수"다. `failedJobs`는 `extract` 작업만 세고 설명으로만 남는다(유실에 더하지 않는다, D2).
- **H03C2F-R2 실패한 추출은 재지 않는다.** 본 단계에서 문서의 작업이 끝났을 때 `extract` 작업이 `dead_letter`·`cancelled`·`superseded`로 새로 끝나 있으면 시간을 적지 않고 그 문서와 상태를 담은 오류로 끝난다(원 spec R4의 검색 규칙과 같다, D4).
- **H03C2F-R3 유휴의 조건을 적는다.** 유휴 표본을 뜨기 직전에 끝나지 않은 작업 수를 읽어 두 유휴 지표에 `openJobs`로 적는다. 0보다 크면 `unverified`에 "처리할 작업이 없는 유휴가 아니다"라는 줄을 수와 함께 더한다.
- **H03C2F-R4 macOS의 RSS 주의.** macOS에서 잰 유휴 RSS의 `note`는 "`ps`의 RSS는 압축된 메모리를 빼므로 메모리가 모자랄 때 낮게 나온다"는 한 줄을 든다. 다른 OS에서는 들지 않는다(D5).
- **H03C2F-R5 신호에도 치운다.** 실행기(본 측정과 복구 단계 모두)가 도는 중에 `SIGINT`·`SIGTERM`을 받으면 띄운 백엔드의 프로세스 묶음을 끝내고 임시 폴더를 지운 뒤 0이 아닌 코드(130·143)로 끝난다. 정상으로 끝나면 신호 처리기를 남기지 않는다.
- **H03C2F-R6 재개는 새 시도로만 본다.** "다시 뜬 뒤 첫 작업 실행"은 어떤 작업의 시도 수가 죽이기 전 스냅숏보다 늘었을 때다. `succeeded` 수가 늘어난 것만으로는 재개로 보지 않는다.
- **H03C2F-R7 재지 못한 것의 목록과 검사.** `unverified`에 LLM 호출의 세 하위 지표(문서당 최대, 질문당, 하루 합)와 "embedding 모델을 올린 상태의 유휴 메모리"가 이유와 함께 든다. 검사기는 `not-measured`인 지표마다 **그 이유와 같은 이유를 가진** `unverified` 줄이 있는지 보고, `failedJobs`가 `null`이면 문제로 적는다. 새로 더한 칸(R1·R3)은 있으면 0 이상의 수인지 본다.
- **H03C2F-R8 결과 파일을 지킨다.** 측정 명령은 **측정을 시작하기 전에** 이름과 대상을 본다. 이름은 영문자·숫자로 시작하고 영문자·숫자·`.`·`_`·`-`만 든다. 대상 파일이 이미 있으면 `--force`가 없는 한 오류로 끝나고 아무것도 쓰지 않는다(D6). README의 명령 줄에 `--force`를 적는다.
- **H03C2F-R9 문서.** `productCommit`의 주석에 "실행 시점의 `HEAD`이고, rebase·amend 뒤에는 `main`에 없는 SHA일 수 있다"를 적는다. 원 spec의 변경 이력에 R7의 유실 계산이 이 spec으로 바뀌었다는 한 줄을 더한다.

## 인터페이스 / 설계 개요

- 결과 형식은 **칸을 더하기만** 한다: `metrics.killRecover.knowledge`, `metrics.idleCpu.openJobs`, `metrics.idleRss.openJobs`, `unverified`의 새 줄. `schemaVersion`은 1 그대로다(D1).
- 계산은 프로세스 없이 시험할 수 있게 순수 함수로 꺼낸다(이름은 구현이 정한다): 근거 줄 수와 문서 수에서 유실·중복을 내는 함수, 스냅숏과 작업 목록에서 재개 여부를 내는 함수, 종류로 거른 실패 작업 수, OS에서 RSS 주의 문구를 내는 함수, 이름·폴더·`--force`에서 대상 경로를 내거나 거절하는 함수. 마지막 함수는 실행기 파일에 두고 명령 파일(`system-measure.main.test-support.ts`)이 부른다(명령 파일은 불러오면 바로 측정을 시작해 시험이 부를 수 없다).
- 근거 줄 수는 제품의 읽기 API(`routes.exploreItem`의 `center.facts[].evidenceCount`)로 읽는다. 강제 종료 뒤의 정본 파일을 실행기가 직접 열지 않는다(열면 실행기가 SQLite 복구를 대신 해 버려 재려는 것을 바꾼다).
- 작업 목록이 잘려 왔으면(`truncated`) 종류로 거르지 못하므로 전체 수를 쓴다(더 많이 세는 쪽).

그림은 넣지 않는다(새 흐름이 없고 있는 단계에 계산과 뒷정리를 더할 뿐이다).

## 잠정 결정

바꾸려면 적힌 자리 하나를 고치면 된다.

- **H03C2F-D1 결과 형식은 더하기만 하고 판 번호는 1, 추적 중인 결과는 다시 만들지 않는다.** 새 칸은 검사기에서 "있으면 본다"이고, 실행기가 실제로 채우는지는 C1·C4가 본다. 그래서 옛 결과는 유효한 채로 남고 새 칸이 없을 뿐이다(그 파일의 유휴는 `brokerBudget.extractionWaitingForBudget` 140이 같은 사실을 이미 적고 있다). 새 칸을 필수로 하려면 `schemaVersion`을 2로 올리고 `--force`로 기본 측정을 다시 돌려 파일을 바꾼다.
- **H03C2F-D2 유실은 근거 줄로 세고 `failedJobs`는 더하지 않는다.** 실패한 추출은 근거 줄이 모자란 것으로 이미 잡히고, 둘을 더하면 한 문서를 두 번 센다. 새 version에 밀려 `superseded`가 된 추출은 지식을 잃은 것이 아니다. 원 spec R7의 "작업 수를 더한다"를 이 줄이 바꾼다. 되돌리려면 R1의 유실 식에 `failedJobs` 합을 다시 더한다.
- **H03C2F-D3 유휴 전에 대기 작업을 비우지 않고 수를 적는다.** 비우려면 호출 예산을 올려야 하고(P7F-R3으로 이제 가능하다) 그러면 기본 측정의 조건과 걸리는 시간이 바뀐다. 비우는 쪽으로 가려면 자식 백엔드가 시작 전에 설정을 쓰게 하고 원 spec D10을 고친 뒤 결과를 다시 만든다.
- **H03C2F-D4 실패한 추출을 만나면 건너뛰지 않고 측정을 끝낸다.** 대역은 실패할 이유가 없으므로 실패는 조사할 일이다. 건너뛰고 수만 적게 하려면 R2의 "오류로 끝난다"를 "표본에서 빼고 `extractionFailed`에 센다"로 바꾼다.
- **H03C2F-D5 macOS의 RSS는 다른 방법으로 재지 않고 주의 한 줄을 적는다.** 판정 환경은 Windows이고 macOS 값은 참고값이다. 바꾸려면 `footprint` 같은 도구의 값을 옆 칸에 더한다.
- **H03C2F-D6 덮어쓰기는 `--force`로만 한다(시각을 붙인 이름을 쓰지 않는다).** 추적 중인 파일 이름이 실행마다 달라지면 README와 시험이 가리킬 이름이 없어진다. 바꾸려면 대상 경로 함수가 거절 대신 시각을 붙인 이름을 돌려주게 한다.
- **H03C2F-D7 신호 처리기는 명령 파일이 아니라 실행기 안에 둔다.** 치울 것(프로세스 번호, 임시 폴더)을 실행기만 안다. 실행이 끝나면 처리기를 떼므로 시험 프로세스에 남지 않는다. 바꾸려면 실행기가 치우는 함수를 내보내고 명령 파일이 신호에 묶는다.
- **H03C2F-D8 배포처 항목은 이 묶음에서 쓰지 않는다.** `docs/site-setup.md`는 이 묶음이 고칠 수 있는 파일이 아니고 항목 번호를 여러 세션이 함께 쓴다. #296의 그 줄은 열어 둔다.

## 미검증 범위

- **근거 줄이 문서당 하나라는 가정.** 정본의 유일 색인(`storage/src/migrations.ts:315`, 사실·원본 version·구절)에서 읽은 것이고 구현 때 C1의 실제 복구 실행(문서 3건)이 `knowledge.evidence` 3을 내 가정이 맞음을 관측했다(시험 빌드 한정).

- `SIGKILL`로 실행기 자신을 죽였을 때의 뒷정리(신호를 받을 수 없어 막지 못한다. 띄운 백엔드와 임시 폴더가 남는다).
